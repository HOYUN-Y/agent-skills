# Terminal 모션 테마

Artificial Insight 브랜드의 **terminal 스타일을 움직이는 영상으로** 옮긴다. **테마와 연출은 고정, 주제는 자유**다. 색·글꼴·로고는 `insight-design-theme` 스킬의 값을 그대로 쓰고, 이 스킬은 그 위에 "어떤 순서로 무엇을 얼마나 오래 움직이는가"(연출 문법)와 그것을 이미 지키는 Remotion 템플릿을 더한다.

템플릿에는 가상의 예시 주제(릴리스 점검 에이전트 4개)가 들어 있다. 예시일 뿐이다. 영상마다 주제에 맞게 문구·데이터·주인공 시각물을 바꾸고, 연출 규칙은 유지한다. 에이전트 이야기가 아니어도 된다: 단계가 있는 과정이면 무엇이든 담을 수 있다(references/direction.md 2절).

## 결과물

- 같은 소스에서 두 영상: `Landscape` 1920×1080, `Portrait` 1080×1920. 둘 다 30fps, 기본 20초(600프레임), H.264, 무음.
- 다시 렌더할 수 있는 Remotion 프로젝트(문구는 `src/data/`, 타이밍은 `src/config/timeline.ts`, 배치는 `src/config/layout.ts`).
- 검증 기록: 정지 프레임, 1초 간격 접촉 시트, 규격·튐 검사 결과.

## 작업 순서

이 목록을 복사해 체크하며 진행한다.

```
- [ ] 1. 브리프 정리(주제·메시지·단계·사실 여부)
- [ ] 2. 콘티: 단계별 사건과 프레임 표
- [ ] 3. 프로젝트 만들기(new_project.sh) → 설치 승인 → 브라우저 준비
- [ ] 4. 주제 옮기기: scenario.ts · hero.ts · timeline.ts
- [ ] 5. 넘침 검사(check:fit) → 정지 프레임 두 화면비 확인 → 사용자에게 보여 주기
- [ ] 6. 초안 렌더 → 최종 렌더
- [ ] 7. 검사: check_video.py, 접촉 시트, 튐 후보 프레임 열어 보기, 원본 대조
- [ ] 8. 보고(+ inspecting-vibe 독립 검수 제안)
```

1. **브리프.** 아래를 짧게 정한다. 대화·자료에 이미 있으면 다시 묻지 않고, 결과를 크게 바꾸는데 빠진 것만 묻는다.
   - 주제와 **한 문장 메시지**(영상이 끝났을 때 남아야 할 것).
   - 단계 2~4개와 단계마다 영어 동사 하나(`01 READ`, `02 TEST` …). 번호는 이 단계 제목에만 쓴다. 카드·파이프라인 블록은 번호 없이 같은 이름을 쓰고, 머리줄 수치로 단계를 또 세지 않는다(direction.md 2절).
   - 일하는 주체(에이전트·도구·사람·단계) 2~4개.
   - 주인공 시각물: 관계·구조면 픽셀 네트워크(`heroKind: 'network'`), 과정·순서·도구 체인이면 단계 파이프라인(`'pipeline'`). 그 밖은 direction.md 7절.
   - **모드: 모의(`demo`)인가 실제 기록(`record`)인가.** 실제 작업·결과를 보여 주면 `record`: 화면의 모든 수치·버전·파일명이 원본 자료에 있어야 하고, 원본에 없는 값(재생 시계, 로그 시각, 토큰, 자동 생성 개수)은 템플릿이 숨긴다. 순서·명령·시점을 원본에서 재구성했으면 배지에 밝힌다(`README 기록 · 순서 재구성`). 모의면 `demo`로 두고 `DEMO · SIMULATED DATA`를 계속 보인다(direction.md 2절).
   - 화면 언어: 한국어 독자 대상(인스타·릴스)이면 제목·태그·결과 문장은 한글, 명령·파일명·도구 이름·로그는 원문 그대로. 영어권 대상이면 영어. 픽셀 제목은 영문 Silkscreen + 한글 Galmuri11로 자동 대체된다.
   - 화면비(기본 둘 다), 길이(기본 20초).
2. **콘티.** [references/direction.md](references/direction.md)를 읽고 3절 시간표·4절 체류 시간 기준에 맞춰 사건별 프레임 표를 만든다. 이 표가 `timeline.ts`가 된다. 사용자에게 표를 보여 주면 이후 수정이 줄어든다.
3. **프로젝트 만들기.**
   ```sh
   sh <이 스킬>/scripts/new_project.sh <작업 폴더>/<영상 이름>
   cd <작업 폴더>/<영상 이름>
   npm install            # 버전 고정 패키지(remotion·react·typescript). 처음 설치는 사용자 승인 후
   npm run setup:browser  # Chrome Headless Shell을 ~/Library/Caches/terminal-motion으로 복사(macOS)
   ```
   스크립트는 템플릿을 복사하고 `insight-design-theme`의 글꼴·라이선스·`brand.json`을 가져온다. 글꼴이 없다고 하면 그 스킬의 `fetch_fonts.py`를 먼저 실행한다(인터넷 필요). 설치·버전·알려진 문제는 [references/production.md](references/production.md).
4. **주제 옮기기.** 수정 지점은 세 파일이다.
   - `src/config/timeline.ts`: 2단계의 표. 한 사건에 여러 자리가 반응하면 주인공 → 창 → 카드·로그 순으로 3~6프레임씩 늦춘다(direction.md 3절).
   - `src/data/scenario.ts`: 배지, 첫 빈 창 줄(`video.idle`, 주제 고유의 첫 줄), 제목, 주체, 수치, 목록, 문서 창, 명령·결과 창, 로그, 마무리 한 줄.
   - `src/data/hero.ts`: `heroKind`와 픽셀 네트워크(묶음, 이름 붙은 노드, 강조 구간 `windows`, 금색 흐름 `flows`, 카메라 `shots`).
   - `src/data/pipeline.ts`: 단계 파이프라인(단계·구간·표시 `marks`). `heroKind: 'pipeline'`일 때.
   예시 내용은 모두 지우고 새로 쓴다. 특히 `record` 모드에서는 예시의 모의 수치(`metrics`의 TOKENS, 주체의 `rate`)를 남기지 않는다.
   화면 자리마다 무엇을 담는지는 direction.md 2절, 글자 수 한계는 8절. 장면에 맞지 않는 창은 부품을 바꿔도 되지만 그때도 1~9절 규칙(한 번에 하나만 일함, 금색 한 뜻, 체류 시간, 이름표 고정)을 지킨다.
5. **정지 프레임.** `npm run typecheck`, `npm run check:fit`(모든 문구가 두 화면비의 자리에 들어가는지 어림. 넘치면 글자 크기가 아니라 문장을 줄인다) 후 `npm run stills`(두 화면비, 기본 프레임 0·130·230·430·480·599, 단계 시점이 바뀌었으면 인자로 넘긴다). PNG를 **모두 직접 열어** 겹침, 잘린 글자, 빈 창, 세로 안전 영역 침범을 찾는다. 첫 영상이거나 큰 구성 변경이면 이 단계에서 사용자에게 보여 주고 애니메이션을 다듬는다.
6. **렌더.** `npm run draft`(절반 크기)로 흐름을 본 뒤 `npm run render`. 출력 이름은 `package.json`에서 주제에 맞게 바꾼다.
7. **검사.**
   ```sh
   python3 -I <이 스킬>/scripts/check_video.py out/<가로>.mp4 --expect 1920x1080@30:600 --sheet out/sheet_landscape.png
   python3 -I <이 스킬>/scripts/check_video.py out/<세로>.mp4 --expect 1080x1920@30:600 --sheet out/sheet_portrait.png
   ```
   접촉 시트를 보고, 튐 후보 프레임은 `npx remotion still ... --frame=N`으로 앞뒤를 열어 의도한 전환(단계 제목 교체, 줄 삽입)인지 결함(이름표 점프, 창이 한 프레임에 꺼짐)인지 가른다. 화면 문장·수치를 브리프와 원본에 다시 맞춰 본다. `record` 모드면 화면 수치마다 원본 위치(파일·줄)를 적은 표를 프로젝트 README에 남긴다.
8. **보고.** 아래 형식. 더 엄격한 확인이 필요하면 `inspecting-vibe`로 독립 검수(영상·모션 기준)를 제안한다. 검수만 요청받았으면 고치지 않는다.

## 보고 형식

- 결과 파일 경로(가로·세로), 규격(해상도·fps·프레임·용량), 렌더 시간
- 검사 결과: 정지 프레임에서 고친 것, 튐 후보와 판정, 남은 문제
- 사용자 확인이 필요한 것: 화면 문구(제목·태그), 핸들(`brand.json`의 `handlePlaceholder`), 모드(demo/record)와 출처 표, 원본에 없어 연출로 재구성한 부분, 확인하지 못한 사실
- 하지 않은 것: 실제 휴대폰 재생, 업로드 후 재인코딩 확인, 독립 검수, 소리

## 하지 말 것

- 테마 값 바꾸기: 색·글꼴·로고 모양·직각·무그림자. 데이터 색(`dataColors`)은 주인공 시각물의 범주 구분에만 쓰는 승인된 예외다. 글자·창·강조에 쓰지 않는다.
- 금색을 두 가지 뜻으로 쓰기. 금색 = "지금 일하는 곳"(단계 제목·실행 중 명령의 `$`, active 창의 첫 점, 진행 중 칸, 파이프라인 `▸`, 선택 노드 테두리, 에이전트 흐름, 로고 i).
- `Date.now()`, `Math.random()`, 네트워크, 직전 프레임 상태에 기대기. Remotion은 여러 탭에서 순서 없이 렌더한다. 무작위는 `random(seed)`.
- 실제 결과처럼 보이는 모의 수치, 원본에 없는 사실·버전·고객 사례, 실제 개인 경로·이메일·키를 화면에 넣기.
- 승인 없이 패키지 설치·버전 변경(three.js 등 새 의존성 포함), 업로드·게시.
- 세로 영상에서 위 220px·아래 420px·오른쪽 140px에 읽어야 하는 글자 두기(릴스 UI가 덮는다). 세로 글자를 템플릿 크기(본문 34px, 보조 28px)보다 줄이기: 휴대폰에서 약 0.36배로 보인다. 글이 넘치면 줄이지 말고 문장을 줄인다.
