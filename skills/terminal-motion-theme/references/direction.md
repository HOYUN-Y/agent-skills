# 연출 문법

이 문서는 terminal 모션 영상의 기준이다. 숫자는 2026-11 세컨드 브레인 에이전트 영상(inspecting-vibe 검수 PASS)과 이 스킬 템플릿에서 실제로 확인한 값이다. 템플릿 코드에는 이미 반영되어 있으니, 주제를 바꾸거나 부품을 새로 만들 때 이 기준을 지킨다.

## 1. 핵심 개념

**흩어진 픽셀이 모여 하나가 된다.** 영상의 처음과 끝이 이 문장이다: 첫 2초에 흩어진 픽셀이 모여 주인공 시각물이 되고, 일이 단계별로 진행된 뒤, 마지막에 그 픽셀이 날아가 로고가 된다. 가운데는 "지금 무엇이 일하고 있는가"를 한 번에 하나씩 보여 주는 터미널 대시보드다.

- 화면은 한 장면이다. 컷 전환 없이 한 대시보드 안에서 상태가 바뀐다.
- 한 순간에 일하는 곳은 하나(많아야 둘)다. 일하는 곳은 밝아지고 금색 표시가 붙는다. 나머지는 가만히 있거나 어두워진다.
- 정보는 터미널 말투로 쓴다: `$ 명령`, `// 설명`, `› 지금 하는 일`, `✓ 결과`, `◀ 표시`.

## 2. 주제를 화면 자리에 옮기기

화면 자리는 고정이고, 담는 내용이 주제마다 바뀐다.

| 화면 자리 | 담는 것 | 에이전트 작업(템플릿 예시) | 프롬프트 기법 소개 | 데이터 분석 과정 |
|---|---|---|---|---|
| 단계 제목 `$ 01 VERB` | 지금 단계, 영어 동사 하나. **화면에서 번호는 여기에만** | 01 SCAN · 02 TEST · 03 SHIP | 01 DRAFT · 02 CRITIQUE · 03 REVISE | 01 LOAD · 02 CLEAN · 03 ASK |
| 주체 카드(2~4개) | 일하는 주체와 지금 하는 일(번호 없이 상태 칸 + 이름) | SCANNER, TESTER … | WRITER, CRITIC, EDITOR | LOADER, CLEANER, ANALYST |
| 머리줄 수치(2~3개) | 진행을 보여 주는 숫자(단계 번호를 또 세지 않는다) | CHANGED, TESTS, TOKENS | TURNS, ISSUES, SCORE | ROWS, NULLS, QUERIES |
| 목록 창(16:9) | 재료의 구조 | 저장소 트리 | 프롬프트 버전 목록 | 데이터 파일·열 목록 |
| 주인공 시각물 | 전체 구조와 지금 다루는 부분 | 모듈 그래프 | 아이디어·피드백 연결망 | 데이터 점 군집 |
| 문서 창 | 읽거나 쓰는 대상 | diff, 소스, CHANGELOG | 프롬프트 본문(고친 줄 타이핑) | CSV 앞부분, 정제 규칙 |
| 명령·결과 창 | 실행과 결과 | `npm test` → ✓/FAIL | 모델 응답 요약 | 쿼리 → 결과 3줄 |
| 로그 | 시간순 사건 | agent.log | session.log | pipeline.log |

- 맞지 않는 자리는 비우지 말고 바꾼다(이 절 끝 참고).
- **진행은 한 체계로.** 단계 제목·카드·파이프라인 블록·머리줄 수치가 같은 진행을 서로 다른 번호나 이름으로 보이면 시청자가 "지금 어디인지"를 잡지 못한다(2회차 독립 검수: 한 화면에 `02 BUILD`·`STAGE 4`·`03 REMOTION`·`03 SCENES`가 함께 나옴). 번호는 단계 제목에만, 카드와 파이프라인 블록은 같은 이름을 쓴다. 원본에 있는 다른 번호(README의 단계 번호 등)는 그 창 안에서만 원문으로 보인다.
- 첫 단계 전 빈 창에는 주제 고유의 첫 줄(`video.idle`, 예: `$ cd <프로젝트>`)을 둔다. `waiting for …` 같은 자리표시 문구는 이름만 바꿔도 통하는 화면이 된다.

### 모의(demo)와 실제 기록(record)

`src/data/scenario.ts`의 `video.mode`로 정한다.

| | demo | record |
|---|---|---|
| 쓰는 때 | 개념·작업 방식을 가상의 예로 보여 줄 때 | 실제로 한 작업·결과(README·로그·검수 기록)를 보여 줄 때 |
| 머리줄 표시(`badge`) | `DEMO · SIMULATED DATA` | 출처, 예: `README 기록`. 순서·명령·시점을 재구성했으면 함께 쓴다: `README 기록 · 순서 재구성` |
| 수치 | 그럴듯하게 지어도 되지만 실제처럼 단정하지 않는다 | **원본에 있는 값만.** 화면 수치마다 원본 파일·줄을 표로 남긴다 |
| 템플릿이 숨기는 것 | — | 재생 시계, 로그 시각, 주체 처리량(토큰), 자동 생성 개수(노드·묶음 수) — 실제 작업 시간·규모로 오해받는다 |
| 주인공 시각물 | 자유 | 모양이 실제 구조가 아니면 창 제목줄에 `illustrative`(템플릿 기본). 이름표는 원본에 있는 이름만 |

- record에서 원본에 없는 연결(어느 단계에서 실패했는지 같은 시점, 명령 표기, 다른 자료에서 가져온 값)은 연출로 재구성한 것이다. 배지에 `재구성`을 쓰고, 출처 표에 표시하고, 보고에 적는다. 수치가 맞아도 `FACTS` 배지 아래에서는 실제 실행 기록으로 읽힌다(2회차 독립 검수).
- 어느 모드든 원본에 없는 사실(버전, 완료 여부, 고객 사례)을 만들지 않는다.
- 맞지 않는 자리 바꾸기: 예를 들어 목록 창 대신 체크리스트, 문서 창 대신 표. 바꾼 부품도 `Panel`(터미널 창)과 아래 규칙을 쓴다.
- 주체가 1개뿐이면 카드 대신 단계 목록을 쓴다. 5개 이상이면 묶는다(카드는 4개까지).

## 3. 장면 순서와 시간표

20초(600프레임, 30fps) 기준. 길이를 바꾸면 비율로 늘이고, 4절 체류 시간을 먼저 지킨다.

| 구간 | 프레임 | 내용 |
|---|---|---|
| 제목 | 0~60 | 0프레임부터 제목이 완성돼 있다(썸네일). 흩어진 픽셀이 모여 주인공 시각물이 된다(약 2.8초). 모든 주체 대기, 빈 창에 `video.idle` |
| 단계 01 | 60~170 | 제목이 `$ 01 VERB`로 타이핑된다. 첫 주체가 RUNNING. 문서 창이 열리고 읽는 막대가 내려간다. 찾은 것마다 표시·강조 |
| 단계 02 | 180~326 | 가장 극적인 사건(실패·발견·충돌)을 둔다. 카메라가 사건 쪽으로 다가간다 |
| 단계 03 | 334~450 | 결과를 만든다. 새 노드가 생기고 선이 자라며 결과 줄 3개가 나온다 |
| 완료 | 458~500 | `DONE` 제목, 모든 카드 `✓`, 완료 배지. 화면이 잠시 정지 상태로 머문다 |
| 마무리 | 500~600 | 대시보드가 16프레임에 걸쳐 사라지고, 픽셀이 로고로 모인 뒤, 브랜드 이름 → `$ 마무리 한 줄` |

- 단계 사이에 6~10프레임 틈을 둔다(카드 상태와 제목이 동시에 바뀌어 눈이 따라갈 시간).
- 단계 안 사건은 12~16프레임 간격으로 하나씩. 같은 프레임에 두 곳이 새로 움직이지 않게 한다.
- 한 사건에 여러 자리가 반응하면 시간차를 둔다: 주인공 시각물(표시·칸) → 3~6프레임 뒤 창(결과 줄·표시) → 다시 3~6프레임 뒤 카드·머리줄 수치·로그. 같은 프레임에 위·가운데·아래가 함께 바뀌면 시선이 흩어진다(2회차 독립 검수). `timeline.ts`에 사건마다 `+4`, `+8`처럼 적는다.
- 세로판 명령·결과 창은 창이 바뀌는 프레임(`from`)에서 6프레임 안에 첫 글자(명령 타이핑)가 시작되게 한다. 늦으면 빈 창이 보인다.

## 4. 체류 시간 기준

읽어야 하는 것이 완성된 상태로 머무는 최소 시간이다. 검수에서 짧다고 지적된 값을 기준으로 정했다.

| 대상 | 최소 | 근거 |
|---|---|---|
| 첫 화면 제목 | 2초 | 썸네일·첫인상 |
| 단계 제목 + 태그 | 타이핑 끝난 뒤 2초 | 단계 길이가 곧 체류 시간 |
| 핵심 결과(답·결과 줄 3개) | 마지막 줄 등장 후 2.5초 | 1.1초일 때 "다 읽기 전에 사라짐" 지적 |
| 완료 요약 | 1~1.5초 | 1.1초에서 충분 판정 |
| 마무리 태그라인 | 1.5초 이상 | 0.9초일 때 "짧음" 지적 |
| 이름표 | 장면 하나(보통 1초 이상) | 짧게 깜빡이면 떨림으로 보임 |

타이핑 속도: 제목 10프레임, 태그 18프레임, 문서 한 줄 약 1.2프레임/글자, 명령 약 0.6프레임/글자.

## 5. 움직임 어휘

`src/lib/anim.ts`에 있다. 새 움직임을 만들기 전에 여기서 고른다. 종류가 적을수록 같은 영상처럼 보인다.

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `appear` | 12프레임, 투명 → 불투명 + 10px 아래에서 올라옴, ease-out cubic | 새 줄, 새 창 내용, 로그 |
| `typed` + `cursorOn` | 글자 단위, 커서 15프레임 주기 | 제목, 명령, 문서에 쓰는 줄 |
| `flash` | 바뀐 순간 1 → 18~30프레임 동안 0, 아이보리 16% 이하 덧칠 | 바뀐 수치·줄·항목 |
| `popIn` | 14프레임, 살짝 넘쳤다 돌아옴(back 2.2) | **새로 생긴 것 하나에만**(새 노드) |
| `windowWeight` | 켜고 끌 때 10프레임 | 강조 구간 |
| 카메라 | 36프레임, ease-in-out cubic | 장면 전환 |
| 진행 칸 | 10칸(세로 8칸), 진행 중 칸만 금색 | 주체 카드 |
| 사라짐 | 16프레임 선형 | 마무리 직전 대시보드 |

- 움직임은 프레임의 순수 함수로만 만든다(production.md 2절).
- 바운스·회전·흔들림·번쩍임 같은 효과는 쓰지 않는다. 터미널은 정확하게 움직인다.

## 6. 시선과 강조

- **active 창은 1~2개.** 테두리가 `slate500`, 제목이 아이보리로 바뀐다. 나머지는 `navy600` 테두리.
- **금색은 한 뜻:** 지금 일하는 곳. 단계 제목의 `$`·커서(현재 단계), 실행 중인 명령의 `$`, **active 창의** 제목줄 첫 점(쉬는 창은 슬레이트), 진행 중인 칸·카드 상태 칸, 파이프라인의 지금 단계 `▸`, 선택된 노드 테두리, 에이전트 흐름 픽셀, 로고 i(마무리의 유일한 금색). 끝난 명령·쉬는 창·마무리 한 줄의 `$`는 슬레이트. 경고·실패에 금색을 쓰지 않는다(실패는 반전 칩 `FAIL`).
- **강조 중 나머지는 밝기 0.45.** 0.3까지 낮추면 그래프가 사라진 것처럼 보였다(검수 지적). 선은 0.25배.
- **강조가 겹치면 최댓값.** 구간 가중치를 더하면 겹치는 순간 밝기가 튄다.
- **바뀐 값은 flash로 알린다.** 숫자만 바뀌면 눈이 놓친다.
- 상태 글자는 정해진 말을 쓴다: `· waiting`, `› 지금 하는 일`, `✓ 결과`, `◀ 표시`, 파이프라인 블록 `▸ 지금`·`✓ 끝남`.

## 7. 주인공 시각물

화면에서 가장 큰 창이다. 템플릿에 두 가지가 있고 `src/data/hero.ts`의 `heroKind`로 고른다(`components/Hero.tsx`가 나눠 그림).

| 종류 | 담을 것 | 모양 |
|---|---|---|
| `network` — `PixelNetwork.tsx` | 관계·연결·구조(저장소, 지식, 데이터 군집) | 묶음(최대 4개)마다 시드로 고정 생성한 노드가 격자 칸에 놓이고, 이야기에 나오는 노드에만 이름이 붙는다 |
| `pipeline` — `PixelPipeline.tsx` | 과정·순서·도구 체인(제작 단계, 처리 흐름) | 단계마다 칸 블록. 그 단계가 일하는 동안 픽셀이 아래부터 쌓여 차오르고, 맨 앞 칸 2개가 금색. 다음 단계로 금색 픽셀이 건너간다. 표시(`marks`)는 블록 위 바탕판(실패는 반전 `✗`) |

주제의 중심이 "무엇이 무엇과 연결되나"면 network, "어떤 순서로 무엇을 했나"면 pipeline. 도구 환경·제작 과정 영상은 대개 pipeline이다. 네트워크 노드를 도구에 억지로 대응시키면 모양이 의미를 잃는다(첫 시험에서 확인).

### 지켜야 할 것(어떤 시각물이든)
- **오프닝:** 넓게 흩어진 자리에서 2~3초에 걸쳐 모인다(픽셀마다 출발이 조금씩 늦음). 선은 픽셀이 거의 모인 뒤 나타난다.
- **카메라:** 장면 단위로만 움직인다(`shots`, 36프레임 이동). 그 사이에는 아주 느린 흔들림만. 강조할 노드들의 가운데로, 확대는 1.6배 이하.
- **강조:** `windows`의 `sel`(크게 1.6배 + 금색 테두리), `lit`(함께 밝힘), `edges`(밝힐 선). 6절 규칙.
- **흐름:** 에이전트가 따라가는 길(`flows`)에 금색 픽셀 3개가 24프레임 주기로 흐른다.
- **새 노드:** `popIn`으로 나타나고, 선이 18프레임 동안 자란 뒤 20프레임에 걸쳐 바탕 선 밝기로 돌아간다.
- **이름표:**
  - 강조 구간의 경계로 장면을 나누고, 장면 안에서는 자리(왼쪽·오른쪽·위아래 비킴)를 바꾸지 않는다. 매 프레임 충돌을 다시 계산하면 이름표가 떨린다.
  - 자리는 장면 시작 24프레임 뒤(카메라가 거의 멈춘 뒤) 정한다.
  - 장면이 바뀌어 사라지거나 자리가 바뀌는 이름표는 8프레임에 걸쳐 사라지고 나타난다.
  - 노드가 화면 밖이면 이름표도 숨긴다. 떠 있는 이름표는 옆 노드의 이름으로 오해받는다.
  - 바탕판(`navy900` + 테두리)을 깐다. 3D·점 위의 글자는 바탕판 없이 읽히지 않는다.
- **묶음 이름표**는 강조가 없을 때만 보이고, 묶음의 바깥쪽에 둔다.
- **HUD**(왼쪽 아래 노드 수·확대, 오른쪽 아래 지금 하는 일)는 바탕판 위에. 세로 영상은 오른쪽 하나만.
- **마무리 연결:** `heroPoints(frame, w, h)`로 마무리 시작 프레임의 픽셀 자리를 내준다. `FinaleLogo`가 그 자리에서 출발한다.

### 다른 시각물로 바꿀 때
관계·구조가 아니면 픽셀 네트워크를 억지로 쓰지 않는다. 같은 약속(오프닝 조립, 장면 단위 카메라·강조, 이름표 규칙, `heroPoints`)을 지키는 새 부품을 만든다.

| 담을 것 | 시각물 |
|---|---|
| 관계·연결·구조 | 픽셀 네트워크(템플릿) |
| 순서·흐름·도구 체인 | 단계 파이프라인(템플릿) |
| 양의 변화 | 픽셀 막대·계단(칸 단위로 쌓임), 5×7 픽셀 숫자 |
| 비교 | 나란한 픽셀 막대 2~4개 |
| 공간·3D 구조 | three.js 복셀(production.md 5절, 새 의존성이라 승인 필요) |

3D 예시: 세컨드 브레인 에이전트 영상(`secondbrain-agent-261108`, 외장 SSD의 `social-media/contents/motion-design-remotion/`)의 `src/components/VoxelBrain.tsx`. 인스턴스 복셀, 발광 점, 프레임 기준 궤도·카메라·강조를 옮긴 사례다.

## 8. 화면비별 배치

같은 장면을 두 배치로 그린다(`src/config/layout.ts`). 세로는 가로를 줄인 것이 아니다. **정보량을 줄이고 글자를 키워** 다시 놓는다.

| | 16:9 (1920×1080) | 9:16 (1080×1920) |
|---|---|---|
| 보는 곳 | 데스크톱, X, 유튜브 | 휴대폰 전체 화면(폭 약 390pt → 0.36배) |
| 안전 영역 | 가장자리 64px 여백 | 위 220 · 아래 420 · 오른쪽 140 · 왼쪽 48px. 그 밖은 디더 띠로 채움. 오른쪽·아래 선에서 20px 더 띄운다(내용 x 920, y 1480까지) |
| 단계 제목 | 54px | 60px(14자 이하) |
| 창 본문 | 15px, 줄 23px | 34px, 줄 48px(휴대폰 약 12pt, 문서 창 한 줄 고정폭 약 37자) |
| 가장 작은 글자 | 13px | 28px(휴대폰 약 10pt). 사실이 들어가는 글자는 이보다 작게 두지 않는다 |
| 주체 카드 | 4열, 지금 하는 일 문장 포함 | 주인공이 `network`면 2열 2줄 한 줄 카드(상태 칸·이름·진행 칸), `pipeline`이면 숨김(같은 진행을 두 번 보이지 않음, 그 높이를 주인공에) |
| 목록 창·범례·노드 수 HUD | 있음 | 없음 |
| 문서·결과 창 | 둘 다 | 한 자리를 나눠 씀. 마지막으로 바뀐 쪽을 보이고, 바꿀 때 창 틀은 두고 내용만 4프레임 사라짐 → 5프레임 등장. 결과 줄의 보조 설명은 다음 줄 |

| 로고 | 30칸 × 14px | 30칸 × 22px |

- 세로 글자 수 한계(한글 1자 ≈ 영문 1.7자): 제목 영문 14자·한글 9자, 태그(`// …`) 영문 34자·한글 20자, 문서 창 한 줄 37자, 결과 줄 39자(보조 설명은 다음 줄 49자), 로그 한 줄 44자, 카드 이름 12자.
- 16:9를 휴대폰 피드에서 보면 세부 글자는 읽히지 않는다(0.2배). 휴대폰용이면 9:16을 쓴다.
- 4:5 등 다른 화면비가 필요하면 `layout.ts`에 배치를 하나 더 만들고 `Root.tsx`에 Composition을 추가한다. 이 표의 기준으로 글자 크기부터 정한다.

## 9. 글자와 색

- 글꼴: 픽셀 제목은 Silkscreen(영문)과 Galmuri11(한글, 테마의 한글 픽셀 글꼴)이 글자마다 자동 대체된다. 창·결과·로그 글자는 모두 JetBrains Mono(한글은 Pretendard로 대체). 같은 파일명이 창마다 다른 글꼴로 보이지 않게 결과 줄도 고정폭이다.
- 화면 언어: 한국어 독자 대상이면 제목·태그·결과 문장은 한글, 명령·파일명·도구 이름·로그는 원문 그대로 둔다(터미널 말투 유지). 영어권 대상이면 영어. 첫 시험에서 한글 큰 제목이 휴대폰에서 더 잘 읽혔다.
- 한글은 고정폭 글자보다 넓다(약 1em). 이름표·칩 폭은 `textWidth()`로 잰다.
- 색: `src/config/theme.ts`(= insight-design-theme `base.css`). 남색·회색·아이보리 + 금색 하나.
- **데이터 색**(`dataColors`: 파랑·보라·민트·장미)은 사용자가 승인한 테마 밖 예외다. 주인공 시각물의 범주 구분(최대 4개)에만 쓴다. 범주가 의미 없으면 `slate`를 쓴다.
- 그라데이션·그림자·둥근 모서리 없음. 덧칠(flash)은 단색 반투명.

## 10. 마무리

- `T.finale`에 대시보드가 16프레임에 걸쳐 사라진다(머리줄 로고·이름은 남음).
- 마무리 시작 프레임의 주인공 시각물 픽셀이 로고 칸으로 날아간다: 칸마다 윗줄부터 14프레임 + 무작위 10프레임 늦게 출발, 26프레임 비행, 비행 65% 지점에서 로고 색(아이보리, i는 금색)으로 바뀐다.
- 로고 칸 수는 22칸 이상(눈이 뭉개지지 않게). 템플릿은 30칸. 눈 대칭 보정이 들어간 `logo.tsx`를 바꾸지 않는다.
- 브랜드 이름은 `finale+34`부터 16프레임 타이핑, `$ 마무리 한 줄`은 `finale+46`부터 10프레임 등장. 마지막 줄이 1.5초 이상 머물도록 `T.finale`을 영상 끝에서 100프레임 앞에 둔다.

## 11. 검수에서 배운 것

이전 영상에서 실제로 지적되고 고친 것. 새 부품을 만들 때 같은 실수를 하지 않는다.

| 증상 | 원인 | 해결 |
|---|---|---|
| 이름표가 떨림 | 매 프레임 충돌을 다시 계산해 좌우가 바뀜 | 장면 단위로 자리 고정 |
| 이름표가 한 프레임에 이동·소멸 | 장면 경계에서 바로 바꿈 | 8프레임 페이드 |
| 노드 없이 떠 있는 이름표 | 노드가 화면 밖 | 화면 밖이면 숨김 |
| 겹치는 강조 순간 밝기가 튐 | 가중치를 더함 | 최댓값 |
| 강조하면 그래프가 사라짐 | 나머지를 0.3으로 | 0.45~0.5 |
| 머리줄이 숫자 따라 흔들림 | 글자 수 기준 너비(`ch`) | px 고정 폭 |
| 3D 위 글자가 안 읽힘 | 바탕 없음 | `navy900` 바탕판 |
| 답을 다 읽기 전에 사라짐 | 체류 1.1초 | 2.5초 |
| 태그라인이 짧음 | 0.9초 | 1.5초 이상 |
| 창 제목과 상태가 어긋남 | 파일 열기 전 제목에 파일명 | 열기 전에는 일반 이름 + `idle` |
| 세로 창이 한 프레임에 통째로 바뀜 | 교체 시 바로 전환 | 내용이 차례로 사라졌다 나타남(겹치면 글자가 뒤엉킴) |
| 세로 창 교체 때 빈 창이 0.15~0.37초 | 창 전체를 페이드, 새 명령이 늦게 시작 | 틀은 두고 내용만 4+5프레임, 첫 글자는 `from` 6프레임 안 |
| 실제 기록 영상에 가짜 수치(시계·토큰·노드 수) | 템플릿 모의 기본값 | `video.mode: 'record'` |
| 도구 지도로 쓴 네트워크가 의미 없음 | 과정 주제에 관계 시각물 | `heroKind: 'pipeline'` |
| 묶음 이름표·창 제목이 가장자리에서 잘림 | 고정 기준점·긴 meta | 영역 안으로 밀어 넣음, 제목 우선·meta가 줄어듦 |
| 로고 눈이 비대칭 | 눈 중심이 칸 격자와 어긋남 | `logo.tsx` 대칭 보정(고치지 않음) |
| 휴대폰에서 사실이 안 읽힘 | 세로 본문 26px·보조 22px(약 9·8pt) | 34·28px, 세로 카드 숨김·한 줄 카드로 높이 확보 |
| 지금 단계를 숫자 하나로 못 잡음 | 제목·수치·카드·블록 번호가 제각각 | 번호는 단계 제목에만, 카드·블록은 같은 이름 |
| 금색 신호가 약함 | 쉬는 창 첫 점·끝난 `$`도 금색 | active 창·실행 중에만 금색 |
| 로그 줄이 0.3초 만에 바뀜 | 로그마다 바로 교체 | 한 줄 1초 이상, 사이 로그 건너뜀 |
| 재구성한 장면이 실제 기록처럼 보임 | `FACTS FROM README` 배지 | `README 기록 · 순서 재구성` |
| 글자를 키운 뒤 버전·용량 끝자리가 잘림 | 줄 길이를 그대로 둠, 표시(`◀ ok`)가 글자를 덮음 | `npm run check:fit`로 미리 잡고 문장을 줄임. 넘치면 `…`로 끝나게 |
| 로그가 제목보다 1초 늦음 | 1초 유지 규칙만 | 단계 제목이 바뀌면 바로 교체 |
| 완료 배지 `8단계`의 8이 작고 어긋남 | Silkscreen 숫자 + Galmuri 한글 | 한글이 섞이면 Galmuri11 하나로(`pixelFont`) |
| 영상 끝까지 남는 1px 금색 세로선(x=47) | Galmuri11의 `$`가 지워진 뒤 자국을 남김 | 프롬프트 `$`는 늘 Silkscreen(`theme.pixel`) |
| 표시 상자가 창 테두리에 붙음 | 폭을 잴 때 `✓ ` 기호를 빠뜨림 | 기호까지 넣어 재고 창 안쪽 12px로 제한 |

`check_video.py`가 보여 주는 튐 후보 중 **단계 제목이 바뀌는 프레임**(제목이 비고 다시 타이핑됨)과 **문서에 줄이 삽입되는 프레임**은 의도한 변화다. 그 밖의 후보는 열어 보고 위 표에 해당하면 고친다.
