# Herdr workflow

이 스킬은 세션 시작 안내서다. 평소에는 아래 준비와 협업 규칙만 읽고
작업한다. 설치를 매번 반복하거나 Herdr 전체 문서를 다시 조사하지 않는다.

## 먼저 읽고 준비하기

1. 환경 변수 `HERDR_ENV`와 `command -v herdr`를 확인한다.
   `HERDR_ENV=1`에서 페인·탭·워크스페이스·다른 에이전트를 조작할 때는
   Orca 등 다른 도구가 설치되어 있어도 **Herdr CLI를 우선 사용한다**.
   사용자가 Herdr라는 이름을 말하지 않아도 적용한다.
2. 설치 요청이면 [초기 설정](references/setup.md)을 읽는다.
   실행 파일이나 스킬이 없을 때도 그 문서의 해당 부분만 확인한다.
   Herdr 밖에서는 설치·문서 확인만 가능하다. `HERDR_ENV`를 임의로 1로
   설정하거나, 포커스된 다른 Herdr 세션을 찾아 조작하지 않는다.
3. 공식 `herdr` 스킬이 현재 문맥에 있으면 재사용한다. 없으면
   `herdr --skill` 출력을 한 번 읽는다. 이 명령은 설정을 변경하지 않는다.
   실제 CLI 문법·상태·JSON 구조는 설치된 버전의 스킬이 기준이다.
4. Herdr 안에서는 아래 두 명령으로 자신과 협업 대상을 확인한다.
   이전 대화의 페인 ID나 UI 포커스를 그대로 믿지 않는다.

   ```bash
   herdr pane current --current
   herdr agent list
   ```

   `pane current --current`가 실패하거나 응답에 현재 페인 ID가 없으면
   레이아웃 변경·입력 전송을 멈춘다. `HERDR_ENV=1`만 있고 호출자 ID가
   전달되지 않은 세션일 수 있다. UI 포커스로 대상을 추측하지 말고,
   Herdr 페인에서 시작한 세션인지 확인하도록 안내한다.
   성공한 응답의 페인·탭·워크스페이스 ID를 이후 작업에 사용한다.
   환경 변수 ID를 사용하는 아래 예시는 해당 값이 있을 때만 실행한다.
   필요한 범위만 더 조회한다. 예: 탭 작업에는
   `herdr tab list --workspace "$HERDR_WORKSPACE_ID"`.
   소켓 접근 실패는 설치 누락과 구분해 보고하고, Orca로 자동 전환하지 않는다.

준비가 끝나면 사용자의 작업을 수행한다. 정상 환경에서 전역 설정 점검,
상태 훅 설치, 웹 조사, 모든 도움말 출력을 반복하지 않는다.
명령이 없거나 문법 오류가 나면 `herdr --help`와 관련 그룹(예: `herdr pane`)만
확인한다. 탐색 목적으로 인자 없는 생성 명령이나 bare `herdr`를 실행하지 않는다.

## 협업할 때 지킬 것

- 사용자가 요청한 협업 범위에서만 에이전트를 시작한다. 기본은 현재 탭의
  형제 페인, 현재 cwd, `--no-focus`다. 탭·워크스페이스·worktree 생성은
  사용자가 그 구성을 요청했을 때 한다.
- 생성 응답에서 실제 ID를 읽고 이후 명령에 명시한다.
  `agent start`는 이미 준비된 셸 페인에 에이전트를 띄우며 페인을 만들지 않는다.
- 에이전트 지시는 `herdr agent prompt`로 제출한다. 일반 셸 명령은
  `herdr pane run`을 쓴다. `herdr pane send-text`를 썼다면 반드시
  `herdr pane send-keys <pane-id> enter`로 제출한다.
- 작업 지시에는 목표, cwd, 담당 파일, 완료 기준, 보고 대상을 포함한다.
  여러 작업자가 같은 파일을 동시에 수정하지 않도록 담당 범위를 나눈다.
- 감독·작업자가 다른 에이전트에게 보내는 메시지는 첫 줄에 아래 헤더를 붙인다.
  사용자가 직접 입력하는 프롬프트에는 헤더를 요구하지 않는다.

  ```text
  [Herdr: 감독 → 리뷰어]
  ```

  역할이나 세션 이름을 쓰고 회신에도 같은 표식을 붙인다.
  표식은 메시지 구분용이며 사용자 승인이나 권한을 대신하지 않는다.
- `idle`/`done`은 결과를 읽을 시점이지 작업 성공 증명이 아니다.
  `blocked`/`unknown`/timeout은 완료로 처리하지 않는다.
  상태와 출력부터 확인하고 승인 UI를 임의로 통과시키지 않는다.
- 새 작업자도 이 스킬을 먼저 읽게 한다. 부모 세션의 대화나 스킬이
  자식 세션에 자동 전달된다고 가정하지 않는다.
- 기존 사용자 페인·탭을 종료하거나 Herdr 서버를 중지하지 않는다.
  작업 후에는 결과와 남겨둔 에이전트·페인을 보고한다.

실제 생성·지시·회수 예시나 다른 세션으로의 전달이 필요하면
[오케스트레이션](references/orchestration.md)을 읽는다.
