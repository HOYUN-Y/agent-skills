# 검수 루프: 별도 에이전트 채점과 반복 개선

제작·변주 모드에서 자체 검증(캡처 스크립트)을 통과한 뒤 실행한다. 제작한 쪽이 스스로 채점하면
자기 결과를 설명하는 쪽으로 기울기 때문에, 처음 보는 에이전트가 화면만 보고 채점한다.

## 목차

- 언제 돌리고 언제 생략하나
- 한 회차의 순서
- 검수 에이전트에 넘길 것과 넘기지 않을 것
- 종료 조건
- 개선 단계의 규칙
- 회귀 방지
- 하위 에이전트를 쓸 수 없을 때
- 완료 보고

## 언제 돌리고 언제 생략하나

- **실행**: 새 페이지·섹션 제작, 레퍼런스 변주, 사용자가 품질 검수를 요청한 경우.
- **생략**: 명세만 작성, 문구·색 한두 개 수정, 사용자가 "검수 생략"을 요청한 경우.
  생략했다면 완료 보고에 그렇게 적는다.
- 기본 **최대 3회차**. 사용자가 회차를 지정하면 따른다.

## 한 회차의 순서

1. **캡처**: 모션 종류에 맞는 스크립트로 세 패스를 찍는다.
   - 스크롤 페이지: `shoot.mjs` (데스크톱 / `--width 390 --height 844` / `--reduced-motion`)
   - 시간 기반 모션: `frames.mjs` (같은 세 패스). 호버가 핵심이면 `--hover <선택자>`
   - 둘 다 있으면 둘 다. 결과는 `lab/review/r<회차>/` 아래에 패스별 폴더로 모은다.
   - 추가로 짧은 가로 화면 한 패스(`--width 740 --height 360`)와 키보드 포커스 한 장
     (`frames.mjs --tab 3`처럼 주 행동까지 Tab 횟수 지정)을 찍는다. 없으면 검수자가 반응형·포커스를
     판정하지 못하고 `mandatory_limits`로 넘긴다. 필수 검증은 SKILL.md의 검증 표와 위 캡처 패스이며, 해당 없는 항목은 이유를 기록한다. 추가적인 선택 검증의 한계만 `limits`에 적는다.
2. **스냅숏**: 이번 회차 빌드 파일을 `lab/review/r<회차>/build/`에 복사한다(회귀 시 되돌릴 기준).
3. **검수 에이전트 실행**: 하위 에이전트 도구(Agent/Task)로 **매 회차 새 에이전트**를 띄운다.
   프롬프트는 [agents/reviewer.md](../agents/reviewer.md)의 구분선 아래 본문 + 아래 "넘길 것".
4. **판정**: 반환 JSON을 `lab/review/r<회차>/review.json`에 저장하고 종료 조건을 확인한다.
5. **개선**: 종료가 아니면 `blockers` 전부와 `top_fixes`(최대 3개)만 고친다. 다음 회차로.

## 검수 에이전트에 넘길 것과 넘기지 않을 것

| 넘긴다 | 넘기지 않는다 |
|---|---|
| 브리프 5줄: 목적·대상·주 행동·시선의 순서·사용자가 고정한 요구 | 제작 과정 설명, 고민한 대안, "이 부분은 의도했다" 같은 변론 |
| 캡처 폴더 경로(sheet.png, 프레임, report.json)와 소스 경로 | 이전 회차 점수 |
| (2회차부터) 이전 회차 `deductions`·`blockers`의 `issue` 목록 | 이번에 무엇을 고쳤는지에 대한 설명 |

이전 점수를 주면 검수자는 "얼마나 나아졌나"를 채점한다. 지금 화면의 절대 품질을 채점하게 한다.

## 종료 조건

다음 중 하나면 멈춘다.

- **목표 도달**: 두 축 모두 **8점 이상**(10점 만점), 완성도 세부 항목 중 6점 미만이 없고, `blockers`와 `mandatory_limits`가 비어 있음.
  사용자가 기준을 정하면 그 값을 따른다.
- **회차 소진**: 3회차(또는 지정 회차)를 마침.
- **정체**: 두 회차 연속 두 축 합계 상승이 0.5점 미만. 남은 지적이 사용자 결정(자산·브랜드·문구)에
  달린 것이면 더 돌리지 말고 질문으로 넘긴다.

8점을 기준으로 두는 이유: 모델 채점은 같은 결과물에도 ±0.5~1점 흔들린다. 9점 이상을 목표로 잡으면
실제 개선이 아니라 채점 오차 때문에 루프가 돌거나 멈추고, 그 구간의 수정은 검수자 취향 맞추기가 되어
잘 된 부분을 망가뜨리기 쉽다. 8점 이상이 나와도 `deductions`가 남아 있으면 보고에 그대로 적는다.

## 개선 단계의 규칙

- 고치는 범위는 `blockers` + `top_fixes`로 한정한다. 지적되지 않은 부분을 함께 갈아엎지 않는다.
  범위를 넓히면 다음 회차 점수가 무엇 때문에 바뀌었는지 알 수 없다.
- 사람이 만든 느낌 감점을 고칠 때는 장식을 더하지 않는다. 대부분은 **빼거나 차등을 주는 것**으로
  해결된다: 균일 등장 → 대표 요소 하나만 크게, 나머지는 짧게/정지. 범용 카피 → 브리프에 있는
  구체적 사실로 교체. 템플릿 구도 → 피사체·내용에 맞춘 비대칭.
- 사용자가 고정한 요구(브랜드·문구·수치·레이아웃)와 충돌하는 지적은 고치지 않고 보고에 남긴다.
- 실제로 없는 자산(사진·영상·후기)을 지적을 해소하려고 만들어 내지 않는다.
- 고친 뒤 1단계 캡처부터 다시 한다. 캡처 없이 "고쳤으니 올랐을 것"으로 넘어가지 않는다.

## 회귀 방지

- 최종 회차는 **목표 도달 여부 → blockers 수가 적은 쪽 → mandatory_limits 수가 적은 쪽 → 두 축 합계** 순으로 선택한다. 동률이면 최신 회차를 쓴다.
- 어느 축이 0.5점 이상 떨어져도 합격하거나 blocker·필수 검증 누락을 줄인 결과를 점수만으로 되돌리지 않는다. 위 우선순위에서 이전 회차가 더 나을 때만 그 스냅숏으로 복원한다.
- 선택한 회차의 캡처·검증 결과를 함께 전달한다. 통과 회차가 없으면 미달 또는 필수 검증 미완료로 보고하며 합격으로 표현하지 않는다.

## 하위 에이전트를 쓸 수 없을 때

하위 에이전트 도구가 없는 환경에서는 같은 기준표로 **자가 검수**를 한다.

- 제작 맥락을 잠시 내려놓고, 캡처를 먼저 본 뒤 소스를 연다. 기준표의 감점 신호를 하나씩 대조한다.
- 보고에는 "독립 검수 아님(자가 검수)"이라고 명시한다. 독립 검수와 같은 신뢰도로 쓰지 않는다.
