# 모션 유형별 설계와 구현

필요한 유형의 절만 읽는다. 수집된 예시는 3D 캐릭터, 영상 배경, UI 등장, 이미지 열 이동에 집중되어 있다. 스크롤 연동은 [내장 스크롤 엔진 지침](scroll-engine.md)을 활용하며 대상 브라우저와 실제 화면에서 확인한다.

## 선택

| 시각적 목적 | 우선 검토 | 비용·한계 |
|---|---|---|
| 제목·버튼의 순차 등장, 가벼운 호버 | CSS 또는 Web Animations API | 작은 변화에 적합하며 텍스트·입력은 DOM에 남는다 |
| 자연·인물·복잡한 배경의 연속 움직임 | 실제 영상 + 정지 대체 이미지 | 디코딩·전송 비용과 자산 확보가 필요하며 영상 내부 요소를 개별 조작하기 어렵다 |
| 이미지·문구가 일정하게 흐름 | CSS 반복 + 필요한 복제 처리 | 자산 수, 간격, 표시 영역에 따라 이음새와 반복 거리를 계산해야 한다 |
| 아이콘·도형·곡선 변형 | SVG/CSS | 기존 벡터·코드 자산을 활용하기 좋다 |
| 다수의 2D 입자·픽셀 효과 | Canvas | 해상도·프레임 비용을 관리하고 접근 가능한 DOM을 별도로 유지해야 한다 |
| 포인터에 반응하는 입체 캐릭터·제품 | WebGL/Three.js 등 실제 3D | 모델 구조·조명·GPU·로딩 대응이 필요하다 |
| 읽는 순서와 연결된 장면 변화 | 스크롤 등장 또는 진행률 연동 | sticky·문서 높이·모바일 조작·동작 감소를 함께 설계해야 한다 |

“모션 페이지”라는 이유만으로 무거운 라이브러리나 3D를 선택하지 않는다. 선택 이유를 사용자에게 설명할 때 효과와 비용을 함께 적는다.

## A. 한 번의 등장과 미세한 상호작용

- 콘텐츠 계층에 따라 순서를 구성한다. 제목이 나오는 동안 주 행동이 과도하게 지연되지 않도록 한다.
- 각 요소의 지연·지속 시간·이동 거리·easing과 최종 상태를 지정한다. 제목의 행별 마스크는 사용 언어의 글리프와 줄 높이를 잘라내지 않아야 한다.
- 레이아웃 정렬이나 글자 비율을 위한 transform은 바깥 요소, 등장 transform은 안쪽 요소로 분리한다.
- 초기 상태는 읽을 수 있는 HTML/CSS로 두고 모션 준비가 된 경우에만 숨김을 적용한다. 완료 이벤트가 오지 않아도 최종 가시 상태로 복구한다.
- CSS 종료 이벤트만 기다리면 동작 감소·요소 제거·애니메이션 교체 때 복구가 누락될 수 있다. 복구 함수는 여러 번 호출해도 같은 최종 상태를 만든다.
- WAAPI를 취소하면 효과가 제거되고 진행 중 `finished` Promise가 거부될 수 있다. 취소 및 복구 경로를 처리한다. [MDN: Animation.cancel](https://developer.mozilla.org/en-US/docs/Web/API/Animation/cancel)
- 포인터 호버 효과는 키보드 포커스 표시를 대체하지 않는다. 터치 환경에서는 호버에만 있는 필수 정보를 만들지 않는다.

## B. 영상 배경과 시네마틱 장면

- 배경 영상과 UI 모션을 구분한다. 이미 움직이는 영상에 확대·이동을 겹칠지는 디자인 목적에 따라 결정한다.
- 장식 배경은 보통 `muted`, `playsinline`, 필요 시 `loop`를 사용한다. 자동재생 성공을 보장한다고 쓰지 않고 `play()` 실패를 처리한다. [MDN: 자동재생 실패 처리](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)
- 정지 이미지나 적절한 배경을 먼저 표시하고 재생 가능한 프레임이 준비된 후 영상으로 전환한다. 다운로드·재생 실패가 UI 표시를 막지 않도록 한다.
- 정지 이미지와 영상의 비율·피사체 위치가 같은지 실제로 확인한다. `object-fit:cover`만으로 서로 다른 크롭이 일치한다고 가정하지 않는다.
- 미러 패딩 제거·특정 높이 비율 등의 수치는 자산별로 계산한다. 예시의 112.5% 또는 −6.25% 같은 값을 다른 영상에 복사하지 않는다.
- 텍스트 가독성은 밝기가 가장 높은 프레임에서도 확인한다. 보호 오버레이는 피사체를 가릴 정도로 과도하게 적용하지 않는다.
- 영상 미제공 상태의 “바람에 움직이는 머리카락” 등은 CSS만으로 구현했다고 표현하지 않는다. 영상 확보, 생성 도구, 다른 시각적 해석 중 가능한 경로를 정한다.
- 배경이 계속 움직이면 일시정지 경로를 설계한다. 동작 감소 시에는 포스터·정지 이미지 등으로 전환한다.
- 화면 밖과 탭 비활성 상태를 구분한다. 자동 재개 전에 사용자가 정지했는지 확인한다. [MDN: Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)

## C. 이미지 열·띠의 무한 이동

- 항목 크기, 간격, 방향, 초당 이동 거리 또는 한 주기 시간을 정의한다. 화면 크기가 바뀔 때 속도를 유지할지 주기를 유지할지 정한다.
- 원본 반복 단위와 복제 단위가 경계 간격까지 동일하도록 구성한다. `translateY(-50%)`는 실제 트랙 구조에서 한 반복 단위와 정확히 일치할 때만 사용한다.
- 반복 단위가 표시 영역보다 짧으면 빈 공간이 생긴다. 필요한 복제 수를 계산하고 리사이즈 때 기존 복제를 다시 복제하지 않는다.
- 복제는 중복 `id`·링크·스크린리더 읽기·Tab 진입을 만들지 않도록 처리한다. 의미 있는 콘텐츠는 접근 가능한 원본 또는 정지 목록을 유지한다.
- 열별 시작 오프셋은 첫 화면의 구도와 연결한다. 임의 값으로 화면 밖 공백을 만들지 않는다.
- 등장 후 반복으로 전환할 때 위치와 위상이 이어지도록 한다. 등장과 마키의 transform을 같은 요소에서 경쟁시키지 않는다.
- 동작 감소·사용자 정지 상태에서도 이미지와 링크를 탐색할 수 있어야 한다.
- 검증은 첫 화면, 주기 직전·직후, 크기 변경 직후를 포함한다.

## D. 포인터 반응과 3D 장면

- 실제 모델의 경계 상자·피벗·부품 이름·좌표계·텍스처·스킨·모프 여부를 확인한 뒤 변환한다. 다른 모델에 기존 눈·안테나 좌표를 그대로 적용하지 않는다.
- 시각적 방향을 정할 때 카메라와 구도, 재질, 조명, 배경, 후처리 순서로 필요한 항목을 명세한다. 특정 색·FOV·광원 종류는 디자인 선택이지 보편 규칙이 아니다.
- 기존 모델을 부드럽게 보이게 하려고 UV·법선·스킨 정보를 일괄 삭제하지 않는다. 모델 특성과 목적을 확인하고 필요한 지오메트리만 복제·수정한다.
- 장면을 순회하면서 자식 효과 메시를 추가해야 하면 먼저 대상 목록을 수집한다. 복제 객체가 공유하는 재질·지오메트리 수정과 해제를 주의한다.
- 피사체의 화면 기준점과 포인터 정규화 좌표계를 일치시킨다. 과도한 회전은 제한하고 시간 간격에 기반해 보간한다.
- idle·pointer active·intro·paused 상태를 구분한다. 프레임 재개 시 큰 시간 간격으로 위치가 튀지 않도록 한다.
- 터치 사용자는 페이지를 정상 스크롤할 수 있어야 한다. 필수 기능을 마우스 추적에만 의존시키지 않는다.
- 캔버스와 카메라·후처리 크기를 함께 갱신한다. 픽셀 비율·그림자·블룸·입자 수는 목표 기기에서 조정하며 임의의 FPS 보장을 하지 않는다.
- 로더는 부분 실패에도 종료한다. 모델 실패에는 대체 지오메트리·이미지, WebGL 실패에는 정적 DOM을 준비한다. 필수 모듈 실패 시에도 핵심 페이지 내용은 남아야 한다.
- 중복 프레임 루프·리스너를 방지하고 언마운트·장면 교체 때 GPU 자원을 해제한다. 공유 자원은 남아 있는 소비자가 있는지 확인한다.
- 새 라이브러리/API 세부 사항은 구현 시 해당 버전의 공식 문서로 확인한다.

## E. 스크롤 모션 — 내장 엔진 또는 작은 구현

스크롤 중심 제작이면 [scroll-engine.md](scroll-engine.md)를 먼저 읽고 내장 엔진 사용을 검토한다. 엔진은 scrub(영상 스크럽)·pin(고정 stage 안 문구 교차)·pan(가로 레일)·flow(일반 섹션)와 cue·reveal·kinetic·parallax·count 장치를 제공한다. 단순 등장이나 엔진 없는 별도 구현 시에도 다음을 확인한다.

- 단순 등장에는 viewport 진입을 트리거로 하는 시간 기반 전환을 고려한다.
- 진행률 연동에는 시작·종료 위치, 범위 밖 상태, 되감기, 빠른 스크롤·앵커 이동 시 결과를 명시한다.
- sticky 또는 고정 장면은 문서 높이와 종료 이후 정상 흐름을 설계한다. 기본 스크롤을 불필요하게 가로채지 않는다.
- 동작 감소 상태에서는 정보가 정상 문서 순서로 읽히도록 한다. pin 해제 후 빈 공간을 남기지 않는다.
- 기존 프로젝트의 라이브러리 또는 대상 브라우저에서 검증 가능한 기능을 사용한다. 명세만 작성할 때 호환성을 확인하지 않았다면 검증할 조건으로 남긴다.
- 내장 엔진을 쓰면 `scripts/shoot.mjs`의 act별 연속 프레임으로 dead scroll·frozen clip·대비를 확인한다. 한 장의 스크린샷은 검증이 아니다.
