# 생성 파일 목록 (catalog)

`inventory.py --write`가 만드는 사람·에이전트용 파일 목록의 형식과 소유권 규칙이다. 갱신 흐름은 [변경분 갱신](incremental-sync.md)을 따른다.

## 형식

- `catalog.md`: 자료원 표(상태·파일 수·목록 링크)와 제외 항목 개수. 라우터에서 직접 링크한다.
- `catalog--<자료원>.md`: 자료원의 상태·형식별 개수와 파일 목록(이름 링크·크기·수정일). 폴더별 소제목으로 묶는다.
- 한 페이지가 80줄을 넘으면 첫 단계 하위 폴더마다 `catalog--<자료원>--<폴더>.md`로 나누고, 그래도 길면 `--p2`, `--p3` 쪽으로 이어 붙인다. 이름이 `<상위>--<부분>.md` 규칙을 따르므로 `check_index.py`가 라우터에서 도달·링크·분량을 검사한다.
- 자료원 루트 폴더 자체는 링크하지 않는다(미등록 최상위 항목 신호를 가리지 않게).
- 목록에는 본문·개인정보·비공개 경로를 넣지 않는다. 존재와 메타데이터만 보여주며 검토 여부를 나타내지 않는다.

## 소유권

- 모든 생성 페이지 첫 줄에 `<!-- secondbrain-index-sync:catalog ... -->` 표식이 있고, 마지막으로 쓴 내용의 해시를 `inventory.json`에 기록한다.
- 같은 이름의 수작업 문서(표식 없음)나 생성 뒤 직접 고친 페이지가 있으면 `--write`는 아무것도 쓰지 않고 중단한다. 설명은 기존 영역 색인·MOC·프로젝트 안내에 둔다. 생성 목록 안에 손으로 설명을 붙이지 않는다.
- 더 이상 생성하지 않는 페이지는 표식·해시가 일치하고 수작업 문서가 링크하지 않을 때만 지운다. 고쳤거나 참조 중이면 남기고 보고한다. 남겨야 할 페이지가 지금은 비공개·제외인 경로를 가리키면 `--write`를 중단하므로, 참조를 정리하고 파일을 지운 뒤 다시 실행한다.
- 수작업 안내는 개별 생성 쪽보다 `catalog.md` 또는 자료원 목록(`catalog--<자료원>.md`)을 링크한다. 쪽 번호 페이지는 파일이 늘면 바뀐다.

## 한계

- `catalog.md` 자체는 쪽으로 나누지 않는다(자료원이 아주 많으면 길어질 수 있다).
- 읽기 분량과 상세 범위(모든 안전한 파일 노출 여부)는 실제 자료원 규모로 다시 정한다.
