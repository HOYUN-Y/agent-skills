# 파일 목록·변경분 갱신

이 문서는 `SKILL.md`를 읽은 뒤에 쓴다. `<스킬 폴더>`는 `SKILL.md`가 있는 폴더다. 절대 규칙(원본 보호·비공개·비밀정보)과 [색인 갱신 절차](index-update.md)의 판단·검증 기준을 그대로 적용한다.

깊은 하위 파일까지 무엇이 있고 무엇이 바뀌었는지는 스크립트가 메타데이터로 찾는다. 무엇을 다시 읽고 의미 색인에 어떻게 반영할지는 에이전트가 판단한다. **목록 조사 완료와 의미 검토 완료는 다른 체크포인트다.**

## 명령

```bash
python3 -I <스킬 폴더>/scripts/inventory.py "<볼트>"                          # 읽기 전용 보고
python3 -I <스킬 폴더>/scripts/inventory.py "<볼트>" --review-out "<work>/targets.tsv"   # 재검토 대상 저장
python3 -I <스킬 폴더>/scripts/inventory.py "<볼트>" --write                  # 목록·생성 페이지 반영
python3 -I <스킬 폴더>/scripts/inventory.py "<볼트>" --mark full --from "<work>/read.tsv"  # 검토 기록
```

- 기본 실행은 아무것도 쓰지 않는다. 본문은 읽지 않는다.
- `--write`만 `.secondbrain/inventory.json`과 최상위 `catalog.md`·`catalog--*.md`(이 스크립트가 만든 파일)를 쓴다. 의미 색인·라우터·원본은 고치지 않는다. 결과가 같으면 파일을 다시 쓰지 않는다.
- `.secondbrain/review-state.json`에 완료 기록을 추가하는 것은 `--mark`뿐이다. `--write`는 현재 비공개·제외 정책에 막힌 검토 기록을 지우기만 하고 완료 기록을 만들거나 바꾸지 않는다.
- `--review-out`·발췌 출력은 볼트와 원본 자료원 밖이어야 한다(`<work>`는 볼트 밖 임시 폴더, 끝나면 지운다).
- `--all`은 기준선 이후 한 번도 검토하지 않은 파일도 재검토 대상에 넣는다(최초 전반 조사용).
- 파일 목록 갱신·변경분 반영 요청이면 `--write`까지 실행한다. 목록만 요청받았으면 거기서 멈추고 본문 해석을 자동으로 시작하지 않는다. 새 자료원 등록·비공개 장부 전환 같은 별도 범위는 절대 규칙의 기존 확인 규칙을 따른다.
- 처음 `--write` 뒤 라우터 탐색 표 근처에 `- 파일 목록(자동 생성): [catalog.md](catalog.md)` 한 줄을 추가한다(운영 규칙 문구는 바꾸지 않는다). 그래야 `check_index.py`가 생성 페이지의 도달·링크·분량을 검사한다.

## 대상과 제외

- 대상: 라우터에 링크로 등록된 `src-*` 자료원과 볼트 안의 최상위 폴더. 등록되지 않은 `src-*` 링크는 목록에서 빼고 보고만 한다.
- 제외(경로를 출력하지 않고 개수만): 비공개 경로와 그 별칭(같은 실제 폴더로 가는 다른 링크), 비밀정보로 보이는 이름, 이름에 주민번호·전화번호·이메일 형식이나 "주민등록"이 들어간 항목, 숨김, 의존성·캐시 폴더.
- 자료원 안의 심볼릭 링크·정션은 따라가지 않는다(순환·중복·자료원 밖 확장 방지). 자료원 루트 링크만 따라간다.
- 비공개 경로가 오프라인 링크 뒤에 있어 지금 확인할 수 없으면, 마지막 `--write`에 저장한 실제 경로의 해시로 별칭을 계속 막는다. 경로 원문은 저장하지 않는다.
- 이름 필터는 정규식이다. 사람 이름 같은 개인정보는 찾지 못한다. 그런 이름은 비공개 목록으로 막는다.

## 변경 판정

| 상황 | 보고 | `--write` 처리 |
|---|---|---|
| 처음 목록화한 자료원 | 기준 목록 생성 | 기준선으로 저장. 검토한 것으로 소급하지 않음 |
| 새 경로 | 추가 후보 | 저장 |
| 크기·수정 시각 변경 | 변경 후보 | 저장 |
| 이전 경로가 없음 | 완전 조사된 자료원에서만 삭제 후보 | 목록에서 뺌(의미 색인은 에이전트가 판단) |
| 같은 이름·크기의 삭제+추가 | 이동 후보 | 자동 확정하지 않음 |
| 연결 실패·권한 오류 | 연결 실패 / 부분 조사 | 이전 목록 유지, 사라진 파일을 삭제로 보지 않음 |
| 자료원 연결 대상 변경 | 보류 | 이전 목록 유지. 확인 후 `--accept-source <이름>` |
| 자료원 링크 제거·등록 해제 | 보류 | 이전 목록 유지. 정리하려면 `--accept-source <이름>` |
| 새 비공개 지정 | 개수만 | 목록·생성 페이지·검토 기록에서 제거. 원문을 다시 읽지 않음 |
| NFC/NFD 정규화 충돌 | 충돌 | 두 경로 모두 보존, `--mark` 거부 |

`size + mtime_ns` 비교는 저렴한 후보 탐지다. 메타데이터가 같은 내용 변경은 잡지 못한다. 전체 해시는 계산하지 않는다.

## 재검토 대상과 검토 기록

재검토 대상은 매 실행마다 현재 순회 결과·저장된 목록·`review-state.json`을 비교해 다시 계산한다. 별도 작업 큐는 없다.

| 사유 | 뜻 |
|---|---|
| 추가·변경 (목록 미반영) | 저장된 기준선 이후 바뀌었고 아직 `--write` 전 |
| 목록 반영 후 미검토 | `--write`로 목록에 넣었지만 검토 기록이 없음. 변경이 0이어도 계속 나온다 |
| 검토 후 변경 | 검토 기록의 크기·수정 시각·자료원 대상이 현재와 다름 |
| 보류 (검토 미완) | `--mark held`로 남긴 항목 |
| 기준선 미검토 | 기준선 파일. `--all`일 때만 목록에 포함 |

보고서는 대상마다 직접 링크한 안내와 상위 폴더를 링크한 안내(역참조)를 함께 보여준다. 생성 목록 페이지는 역참조에서 뺀다. 영향받는 질문·프로젝트 판단은 에이전트가 정한다.

흐름:

1. `inventory.py --review-out <work>/targets.tsv` — 열: 경로, 크기, 수정 시각, 자료원 ID, 사유.
2. 필요한 본문만 발췌: `manifest.py <볼트> <work>/m --paths <work>/targets.tsv`, `doc_manifest.py <볼트> <work>/m --paths <work>/targets.tsv`. 목록의 각 경로는 순회와 같은 규칙으로 다시 검사한다.
3. 에이전트가 역참조 안내·프로젝트 정본·질문을 확인하고 의미 색인을 보강한다(절차 3~4단계).
4. 실제로 읽고 반영한 행만 남긴 TSV로 `--mark <수준> --from <파일>`. 수준: `head`(제목·앞부분), `relevant`(관련 본문), `full`(전문), `held`(보류). 현재 크기·수정 시각·자료원 ID가 TSV와 다르면 기록하지 않고 "읽은 뒤 바뀜"으로 남긴다.
5. 기록에는 본문을 넣지 않는다(크기·수정 시각·자료원 ID·수준·날짜만).

발췌 추출 성공은 검토 완료가 아니다. `doc_manifest.py`의 범위 열(예: PDF 앞 3쪽, XLSX 공유 문자열만)을 보고 실제 읽은 수준으로 기록한다.

병렬 작업자는 담당 의미 색인만 고친다. 목록 기준선·검토 기록·라우터·MOC·비공개 설정은 감독 세션 한 곳에서만 쓴다. 작업자가 읽은 뒤 원본이 바뀌면 `--mark`가 거부하므로 재검토 대상으로 남는다.

## 보고

목록 파일 수, 이번 순회 파일·폴더 수와 경과 시간, 변경 후보 수, 재검토 대상 수, 현재 원본과 일치하는 검토 수(수준별)를 따로 적는다. 목록 갱신만 했으면 본문 조사·의미 색인 반영·질문 검증까지 했다고 보고하지 않는다. 자료원이 연결 실패·부분 조사·보류이면 그 범위를 적는다.
