# 세컨드 브레인 색인 동기화

탐색 구조는 두 축이다. 두 구조 모두 안내 문서에만 적용하고, 실제 폴더를 이 순서로 재정리하지 않는다.

- **영역 축 (어디에 있나):** 최상위 라우터 → 영역별 안내(색인: 업무 `work.md`, 개인 `personal.md` 등) → (하위 색인) → 필요한 자료
- **주제 축 (무엇과 관련 있나):** 최상위 라우터 → 주제 MOC(`moc-배포.md`, `moc-기획.md` 등) → 필요한 자료

업무와 개인은 영역 색인에서만 나눈다. 주제 MOC는 업무·개인 자료를 함께 링크한다. 자료 하나가 영역 색인 하나와 주제 MOC 여러 개에 동시에 링크될 수 있다.

추가·변경·이동·삭제된 자료를 확인하고, 그와 관련된 내용(사용자 설명, 기존 안내, 메타데이터, 읽은 텍스트)을 근거로 판단한다. 명확한 항목은 처리하고, 근거 부족·충돌·읽기 실패 항목만 보류한다.

`<스킬 폴더>`는 이 `SKILL.md`가 있는 폴더다(Claude Code·Codex 모두 같은 파일을 쓴다). 아래 명령의 스크립트는 `<스킬 폴더>/scripts/`에 있다.

macOS·Linux·Windows에서 동작한다. 운영체제별 차이:
- 파이썬 명령: macOS·Linux는 `python3`, Windows는 `py -3`(없으면 `python`). 아래 명령의 `python3`를 바꿔 쓴다. 경로는 Windows에서도 `/`로 적어도 된다.
- 외부 폴더 링크: macOS·Linux는 `ln -s "<원본>" "<볼트>/src-<이름>"`, Windows는 관리자 권한이 필요 없는 정션 `cmd /c mklink /J "<볼트>\src-<이름>" "<원본>"`.
- 설정 파일 위치: `~/.config/secondbrain-index-sync/vault` (Windows는 `%USERPROFILE%\.config\secondbrain-index-sync\vault`).

작업 폴더(볼트)는 다음 순서로 정한다.
1. 사용자가 지정한 경로
2. 현재 작업 폴더 최상위에 `CLAUDE.md` 라우터가 있으면 그 폴더
3. 설정 파일 `~/.config/secondbrain-index-sync/vault`에 적힌 경로 (한 줄)
4. 셋 다 없거나, 1·3에서 고른 폴더에 `CLAUDE.md` 라우터가 없으면 [처음 설정](references/setup.md)을 읽고 진행한다. 설정을 마치면 원래 요청으로 돌아간다.

라우터(`CLAUDE.md`), 영역 색인, 하위 색인, 주제 MOC와 프로젝트 안내(`project-<이름>.md`)는 모두 작업 폴더 최상위에 둔다.

## 절대 규칙

- 원본 자료와 폴더는 이동·이름 변경·수정·삭제하지 않는다. 쓰는 대상은 라우터, 영역 안내(색인), 하위 색인, 주제 MOC, 프로젝트 안내, 필요할 때 만드는 `INDEX.md`, 사용자 확인 후 만드는 `AGENTS.md`·`.secondbrain/topics.json`·`.secondbrain/private-paths.txt`뿐이다. 색인에서 링크한 원본 노트(`.md` 포함)는 색인 문서가 아니므로 고치지 않는다.
- **외부 자료 폴더:** 볼트 최상위의 `src-*`는 원본 폴더(Google Drive 등)로 가는 심볼릭 링크이고, 라우터의 '외부 자료 폴더' 표에 등록돼 있다.
  - `src-` 링크 안의 파일은 원본이다. 이동·이름 변경·수정·삭제하지 않고, `src-` 링크 자체도 삭제하지 않는다. 색인은 `src-<이름>/...` 경로로 링크한다.
  - 새 외부 폴더 추가는 사용자 확인 후에만 한다: 위 운영체제별 방법으로 `src-<이름>` 링크를 만들고, 라우터 표에 행(링크·원본 위치·영역)을 추가한다. 용도를 알 수 없으면 영역에 "용도 확인 필요"라고 적는다.
  - 링크 안의 비공개 경로는 `src-<이름>/<하위경로>` 형식으로 비공개 목록에 적는다. 이름만 쓰면 링크 안 경로에 적용되지 않는다.
- 라우터의 **운영 규칙**과 공통 작업 지침은 그대로 보존한다. 사용자가 요청하지 않으면 규칙 문구를 바꾸지 않는다. 탐색용 표·목록(영역 색인 표, 주제 MOC 표 등)의 항목은 이 절차에 따라 추가·수정·삭제할 수 있다.
- 비공개 자료는 읽지도, 색인하지도, 링크하지도 않는다. 비공개 목록은 라우터에서 "비공개"가 적힌 줄의 백틱 이름과, 명시적으로 지정한 비공개 장부의 합집합이다.
  - 비공개 경로를 추가할 때는 `<볼트>/.claude/settings.json`의 `permissions.deny`에 `"Read(/<경로>)"`와 `"Read(/<경로>/**)"`도 추가한다(`/`는 볼트 기준). Claude Code는 이 규칙으로 읽기를 막는다. Codex에는 적용되지 않으므로 라우터와 지정 장부를 직접 확인해야 한다.
- 목록이 길면 사용자 확인 후 `.secondbrain/private-paths.txt`에 볼트 상대경로를 한 줄씩 두고, 라우터에 `- 비공개 장부: .secondbrain/private-paths.txt`를 일반 텍스트로 적는다(실제 표식에는 백틱을 쓰지 않는다). 기존 라우터 목록도 계속 적용한다.
  - UTF-8(BOM 허용), 빈 줄·`#` 주석, NFC/NFD·CRLF를 지원한다. 절대경로·상위 이동(`..`)·역슬래시·와일드카드(`*`, `?`)는 금지한다. 대괄호는 실제 파일명의 문자로만 취급한다. 아직 존재하지 않는 차단 경로도 보존한다.
  - **원본 열람·검색 전에 라우터와 지정 장부를 읽는다.** 장부가 남아 있는데 표식이 없거나 표식의 서식을 해석할 수 없는 경우, 지정 장부 누락·읽기 실패·형식 오류 시 자료 탐색을 중단한다. 장부로 옮겨도 Claude 차단 규칙을 유지한다.
  - 기존 볼트는 자동 전환하지 않는다. 다른 소비자의 비공개 목록 처리도 확인하고, 전환 전후 합집합과 차단 규칙이 동일함을 검증한다. 장부를 자동으로 비우거나 의심 자료를 임의로 허용하지 않는다.
- 인증 파일·키·토큰 등 비밀정보로 보이는 자료는 별도 지정이 없어도 열지 않고 색인하지 않는다. 이 폴더에서 `.key`는 Keynote 파일이다.
- 자료 링크는 반드시 `[자료이름](상대경로)` 형식으로 쓰고, 상대경로는 그 링크를 쓰는 문서 위치를 기준으로 한다.
  - 경로를 일반 텍스트나 코드 표기로만 적지 않는다.
  - 예외는 비공개 자료뿐이다. 이름만 적고 링크하지 않는다.
- "자주 쓰는 자료"는 사용자가 지정한 것만 올린다.
- Codex는 `AGENTS.md`를 작업 지침으로 읽는다. 데이터 라우터는 계속 `CLAUDE.md`다. `AGENTS.md`가 없으면 한 줄 안내 `이 작업 폴더의 세컨드 브레인 데이터 라우터로 CLAUDE.md를 읽으세요.` 생성을 제안하고, 사용자 확인 후에만 만든다. 기존 `AGENTS.md`는 수정하지 않는다.

## 작업 고르기

- 자료 변경 반영·링크 점검·색인 분할·MOC 갱신: 아래 절차 1~5단계를 따른다.
- "전체 재색인", "내용 기준으로 다시 색인", "주제별로 다시 묶어줘" 요청이나 큰 작업 뒤 정기 점검(월 1회 정도): [전체 재색인](references/full-reindex.md)을 **반드시 읽고** 진행한다. 위 절대 규칙, 절차 3단계의 용도 설명·중복 방지·색인 분할·주제 MOC·프로젝트별 정본 연결 규칙, 4단계 검증 기준을 그대로 적용한다.
- 새 볼트 요청이나 위 볼트 경로 결정 4번에 해당할 때: [처음 설정](references/setup.md)을 읽고 진행한다.

## 절차

### 1. 현재 구조 읽기

- `CLAUDE.md`(라우터)를 읽는다. `AGENTS.md`가 있으면 그것도 읽는다.
- 라우터의 분야 표에 연결된 분야 안내와, 분야 안내가 링크한 하위 색인(`<분야색인명>--<주제>.md`, `<분야색인명>--<주제>--<소주제>.md`)을 모두 읽는다. 라우터에서는 이 형식을 "서브 인덱스"라고 부를 수 있다.
- 운영 규칙, 비공개 목록과 지정 장부, 분야와 폴더의 대응을 파악한다. 질문과 관련된 프로젝트 안내도 읽는다.

### 2. 변경 감지

다음 명령을 실행한다. 스크립트는 색인 문서(라우터, 최상위 `.md`, `INDEX.md`)만 읽고, 나머지 자료는 이름과 메타데이터만 본다. 비공개 경로(하위 경로 포함)와 비밀정보로 보이는 이름은 읽지 않는다.

```bash
python3 -I <스킬 폴더>/scripts/check_index.py "<작업 폴더>"
```

보고서 항목별로 처리한다.

| 항목 | 의미 | 처리 |
|------|------|------|
| 새 최상위 항목 | 라우터·안내 어디에도 링크가 없음 | 3단계 "새 분야 판단" |
| 깨진 링크 + 같은 이름 후보 1개 | 이동으로 보임 | 링크를 새 경로로 고친다 |
| 깨진 링크 + 후보 0개 | 삭제로 보임 | 사용자가 삭제를 언급했으면 항목을 지우고, 아니면 보류한다 |
| 깨진 링크 + 후보 2개 이상 | 충돌 | 보류한다 |
| 색인 문서보다 최근에 바뀐 하위 항목 | 추가 또는 변경 | 해당 분야 안내에 반영할지 판단한다 |
| 빈 폴더 | 내용 없음 | 안내에 "파일 없음"으로만 표시한다 |
| 비밀정보로 보이는 이름 / 비공개 링크 | 금지 대상 | 비공개 링크는 제거하고, 비밀정보 항목은 색인하지 않는다 |
| 중복 링크 | 같은 문서에서 같은 대상을 두 번 링크 | 이번 작업에서 생긴 중복이면 하나로 합친다 |
| 읽지 못한 색인 문서 | 권한·인코딩 문제로 열 수 없음 | 보류하고 사용자에게 알린다 (나머지 점검은 계속한다) |
| 인코딩 불일치 | 한글 NFC/NFD, 공백, `:` 표기 차이 | `--normalize`로 링크만 디스크 표기에 맞춘다 |
| 8000자를 넘는 라우터 | 안내가 실질적으로 김 | 핵심 진입점만 유지하고, 긴 비공개 목록은 승인된 장부 전환을 검토한다 |
| 100줄을 넘는 색인 | 분야 색인이나 하위 색인이 너무 길어짐 | 3단계 "색인 분할"에 따라 나눈다 |
| 하위 색인 이름 규칙 위반 | 이름이 `<상위 색인명>--<주제>.md` 형식이 아님 | 규칙에 맞는 이름으로 새로 쓰고 상위 색인 링크를 고친다. 옛 파일은 사용자 확인 후 정리한다 |
| 연결되지 않은 하위 색인 | `--`가 들어간 색인이 있지만 어디서도 링크하지 않음 | 같은 주제를 나눌 때 새로 만들지 말고 이 파일을 재사용해 상위 색인에 다시 연결한다. 주제가 맞지 않으면 보류한다 |
| 라우터에서 닿지 않는 안내 문서 | 최상위 `.md`가 라우터·분야 안내 어디에도 연결되지 않음 | 분야 안내로 확인되면 라우터 표에 연결하고, 아니면 보류한다 |
| 코드 표기로만 적힌 경로 | 실제 경로가 링크 없이 `코드` 표기로만 있음 | `[자료이름](상대경로)` 링크로 바꾼다 (비공개 이름은 예외) |

- 사용자가 바뀐 자료를 직접 말했다면 그 내용을 우선 근거로 삼는다.
- `src-` 링크는 폴더처럼 취급해 그 바로 아래까지 본다. 깨진 링크의 이동 후보 검색은 링크 안(순환 링크는 한 번만)도 찾는다.
- 스크립트는 자료 폴더를 최상위와 그 바로 아래까지만 본다. 더 깊은 변경은 사용자가 말한 경로를 직접 확인한다. 안내·색인 문서는 라우터에서 링크를 따라 깊이 제한 없이 모두 점검한다.

### 3. 판단과 반영

**새 분야 판단**

- 사용자 설명, 기존 안내의 설명, 기존 분야와의 관계로 분야가 분명할 때만 연결한다.
- 기존 분야의 하위 자료로 보이면 해당 분야 안내의 주제·프로젝트 묶음에 추가한다.
- 새 영역(업무·개인 등)으로 확인되면 라우터의 영역 색인 표에 행을 하나 추가한다.
  - 그 분야의 안내가 이미 있으면 재사용한다.
  - 안내가 없으면 기존 안내 형식을 따르는 짧은 안내를 새로 만든다. 들어갈 내용은 라우터 복귀 링크, "자주 쓰는 자료", 주제별 묶음이다.
- 폴더 이름만으로는 어느 분야인지 판단할 수 없으면 보류한다.

**용도 설명**

- 텍스트 자료는 필요한 만큼 읽어 한 줄로 쓴다.
- 이미지, PDF, 영상, 압축 파일, Keynote·Pages·HWP처럼 내용을 확인하지 못하는 자료는 기존 안내 설명과 메타데이터로 확인되는 범위만 적는다. 메타데이터는 형식, 크기, 수정일, 하위 파일 수 등이다.
- 파일명만 보고 용도나 버전을 추측하지 않는다. 근거가 없으면 "용도 확인 필요"라고 적는다.
- 한 항목은 한 줄로 쓴다. 분야 안내는 주요 진입점 중심으로 짧게 유지한다.
- 라우터에는 개별 파일을 나열하지 않는다.

**중복 방지 (재실행 안전)**

- 추가하기 전에 같은 대상이 이미 그 문서에 링크돼 있는지 확인한다. 있으면 기존 줄의 설명만 보강하고 새 줄을 만들지 않는다.
- 문서 대상은 같은 분야에 이미 있는 안내를 쓴다. 같은 용도의 새 문서는 만들지 않는다.

**색인 분할 (100줄 기준)**

- 분야 색인이 100줄을 넘으면 주제·프로젝트 묶음 단위로 하위 색인 `<분야색인명>--<주제>.md`로 나눈다. 분야색인명은 분야 색인 파일 이름에서 확장자를 뺀 것이다(예: `personal--포트폴리오.md`).
- 하위 색인이 다시 100줄을 넘으면 `<분야색인명>--<주제>--<소주제>.md`로 한 단계 더 나눈다.
- **기존 하위 색인을 먼저 재사용한다.** 같은 주제의 하위 색인이 이미 있으면(연결이 끊긴 것 포함) 그 파일에 항목을 옮기고, 같은 주제의 새 파일을 만들지 않는다.
- 하위 색인은 분야 색인과 같은 위치에 둔다. 첫머리에는 상위 색인으로 돌아가는 링크를 둔다.
- 기존(상위) 색인에는 그 주제의 짧은 설명과 하위 색인 링크만 남긴다. 옮긴 항목이 상위 색인에 중복으로 남지 않게 한다.
- 100줄 이하인 색인은 나누지 않는다. 라우터에 "색인 현황" 줄이 있으면 함께 갱신한다.

**주제 MOC**

- MOC는 한 주제(예: 배포, 운영, 기획)의 자료를 업무·개인 구분 없이 링크로 모은 안내 문서다. 이름은 `moc-<주제>.md`로 하고, 첫머리에 라우터로 돌아가는 링크를 둔다.
- 라우터에 "주제 MOC" 표를 두고 MOC마다 한 줄씩 연결한다. 표가 없으면 기존 운영 규칙을 바꾸지 않고 표만 추가한다.
- 새 자료나 바뀐 자료가 기존 MOC 주제에 해당한다는 근거(사용자 설명, 읽은 텍스트, 기존 안내 설명)가 있을 때만 그 MOC에 링크를 추가한다. 파일명만으로는 주제를 추측하지 않는다.
- 영역 색인에 이미 있는 자료도 MOC에 함께 링크할 수 있다. 같은 MOC 안에서만 중복을 막는다.
- 새 MOC는 사용자가 요청했거나, 기존 MOC에 맞지 않는 같은 주제 자료가 3개 이상 근거와 함께 확인될 때만 제안한다. 사용자 확인 후 만든다.
- MOC도 100줄을 넘으면 색인 분할 규칙에 따라 `moc-<주제>--<소주제>.md`로 나눈다.
- 비공개·비밀정보 자료는 MOC에도 링크하지 않는다.

**프로젝트별 정본 연결**

- 날짜·문서 폴더와 코드 저장소가 분리되어 같은 프로젝트의 정본을 찾기 어려우면 짧은 `project-<이름>.md` 안내를 만들고 라우터의 프로젝트 표에서 연결한다. [프로젝트 안내 틀](templates/project.md)을 참고한다. 모든 프로젝트에 일괄 생성하지 않는다. 프로젝트 안내는 라우터 표에서 직접 연결한다(이름에 `--`가 없는 안내를 MOC에서만 연결하면 기존 명명 검사 대상이 될 수 있다).
- 문서와 코드·설정의 연결 근거, 기준 시점과 상태(계획·로컬·QA·운영), 후속 변경 기록, 관련 날짜와 질문별 근거를 링크한다. 실행 코드가 어떤 규칙표를 읽는지 확인했으면 그 파일까지 연결한다. 최신 정본을 확인하지 못하면 정본 후보라고 표시한다.
- README 하나가 보류됐다고 프로젝트 전체를 숨기지 않는다. 안전한 폴더·파일로 진입점을 남기고 보류된 자료만 제외한다. 비공개 경로 아래의 파일은 대체 진입점으로 쓰지 않는다.
- 상위 색인은 짧은 설명과 상세 안내 링크를 두고, 같은 해설을 여러 곳에서 다시 쓰지 않는다. 사본은 기준본·기준일과 후속 변경 관계를 확인하며, 날짜나 파일명만으로 최신본을 단정하지 않는다.
- 심화 요청은 하위 문서를 재귀 확인하되 제목·소제목·도입부 추출과 본문·전문 검토 수를 구분한다. 계획·시험·실제 반영을 구분하고, 입출력 근거가 없으면 선후 관계 대신 관련 자료로 연결한다.
- 새 볼트·내용 재색인·연결 품질 보강에서는 대상 프로젝트에 맞는 질문을 고른다(예: 출처·갱신, 전처리·매핑, 구현·계약, 검증·배포, 운영 한계, 결정·후속 변경). 모든 프로젝트에 같은 항목을 강제하지 않는다. 사용자 보고나 이번 탐색 기록에서 우회·실패가 확인됐다면 그 프로젝트의 기존 안내를 보강한다. 경로 이동만 반영하는 단순 갱신은 영향받는 연결만 확인한다.

**INDEX.md**

- 기존 README나 안내로 부족하고 하위 자료를 묶는 것이 탐색에 실제로 도움이 될 때만 짧게 만든다.
- 모든 폴더에 만들지 않는다.

### 4. 검증

다시 실행한다. 한글 표기 차이가 있으면 `--normalize`를 붙여 실행한다.

```bash
python3 -I <스킬 폴더>/scripts/check_index.py "<작업 폴더>" --normalize
```

- 비공개 링크와 이번 작업에서 생긴 중복 링크는 0이어야 한다.
- 깨진 링크와 읽지 못한 색인 문서는 0이거나, 남은 것마다 보류 이유가 있어야 한다.
- 100줄 초과 색인, 연결되지 않은 하위 색인·안내 문서, 코드 표기로만 적힌 경로는 0이거나, 남은 것마다 보류 이유가 있어야 한다.
- 새로 추가한 링크마다 **라우터 → 분야 안내 → (하위 색인) → 자료** 또는 **라우터 → 주제 MOC → 자료**로 실제로 따라갈 수 있는지 확인한다. 스크립트의 "점검 대상 문서" 목록에 그 안내·하위 색인이 들어 있으면 라우터에서 닿는 것이다.
- 링크 정합성과 답변 완전성은 별개다. 실제 질문 3~5개로 라우터 → 프로젝트/주제 → 정본·후속 기록 경로를 확인하고, 기준 시점·보류 사유와 남은 공백을 기록한다. 외부 호출·배포 없이 확인 가능한 범위로 한정한다.
- 위 질문은 이번 변경 범위에서 표본으로 고른다. 기존 실패 질문이 있으면 포함한다. 의도한 하위 안내를 따라가는 것은 정상 경로이며, 안내된 링크 밖에서 다시 검색해야 근거를 찾는 경우를 우회로 기록한다.
- 경로 도달과 답변 충족을 따로 판정한다. 질문의 하위조건마다 근거·기록일·미확인을 구분한다(예: 출처를 찾아도 갱신 주기는 미확인일 수 있다). 경로가 짧아져도 하위조건이 남으면 부분 답변이며 완전한 해소로 보고하지 않는다. 실제 본문 확인과 기존 색인 설명 재사용도 구분한다.
- 우회·미도달이 확인되면 비공개 장부를 대조한 안전한 근거로 기존 안내를 보강하고 같은 질문을 다시 시험한다. 필요하면 라우터·MOC의 질문 설명도 맞추되 기존 링크를 보존한다. 요청 범위에서 근거를 못 찾으면 미확인으로 남긴다. 공백을 채우려고 비공개 자료를 우회하거나 승인 없는 외부·운영 조회로 확대하지 않는다. 독립 세션·병렬 검증은 요청되거나 승인된 경우에만 추가한다.
- 원본 이동·새 프로젝트 생성 작업을 수행했다면 같은 턴에 해당 안내를 갱신한다. 원본 작업 자체의 승인 범위는 넓히지 않는다.
- 스크립트를 수정했으면 `check_index.py --selftest`, `manifest.py --selftest`, `doc_manifest.py --selftest`, `build_topics.py --selftest`를 실행한다.

### 5. 결과 보고

다음 항목을 짧게 보고한다.

1. **변경된 문서:** 파일별로 추가·수정·삭제한 줄을 요약한다.
2. **연결 경로:** 새로 연결한 자료마다 `라우터 → 안내 → (하위 색인) → 자료` 경로(MOC에 추가했다면 `라우터 → MOC → 자료`)를 적는다. 색인을 나눴다면 어떤 항목이 어느 하위 색인으로 옮겨졌는지도 적는다.
3. **변경 이유와 근거:** 사용자 설명, 기존 안내, 메타데이터, 읽은 텍스트 중 무엇을 근거로 삼았는지 적는다.
4. **보류 항목:** 근거 부족, 충돌, 읽기 실패 항목과 각 이유, 그리고 사용자가 확인할 내용을 적는다.
5. **미처리 범위:** 점검하지 않은 깊이, 비공개·비밀 제외 자료, 내용을 열지 않은 형식 등을 적는다.

일부만 확인했다면 확인한 범위를 그대로 적는다. 스크립트 범위(최상위 + 바로 아래)를 넘는 변경을 모두 확인하지 않았다면 "전체 점검 완료"라고 쓰지 않는다.
질문별 연결을 보강했다면 재시험의 경로·답변 충족 결과와 남은 공백도 보류 항목·미처리 범위에 포함한다. 링크 오류 0개나 연결 파일 수만으로 탐색 품질을 보증하지 않는다.
