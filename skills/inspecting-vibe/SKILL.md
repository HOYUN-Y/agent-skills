# Inspecting Vibe

사용자가 디자인 용어를 몰라도 결과물의 목적과 느낌을 전문적인 관찰 기준으로 바꾸어 검수한다. 설명과 보고는 한국어 존댓말을 기본으로 하며, 전문 용어는 실제 문제를 설명하는 말과 함께 쓴다.

## 기본 동작

- Codex 호출: `$inspecting-vibe 지금 만든 결과물 검수하고 개선해줘.`
- Claude Code 호출: `/inspecting-vibe 지금 만든 결과물 검수하고 개선해줘.` Claude Code에서 발견하려면 스킬 폴더가 `~/.claude/skills/inspecting-vibe/` 또는 프로젝트의 `.claude/skills/inspecting-vibe/`에 있어야 한다. Codex 설치만으로 Claude 설치까지 완료된 것은 아니다.
- 검수만 요청했거나 수정 의사가 불분명하면 진단만 한다. 스킬 호출 자체를 수정·게시·배포 허가로 간주하지 않는다. 기존 대화에서 개선까지 요청했다면 다시 허가받지 않는다.
- 수정이 승인된 경우 최초 검수 후 수정·재검수를 기본 3회까지 수행한다. 아래 중단 조건에 해당하면 그 전에 종료한다. 미달이 남고 개선 가능한 경우 최대 5회까지 자동 연장한다. 기준을 달성하면 즉시 종료한다. 사용자 지정 횟수·기준이 있으면 우선한다.
- 별도의 검수 에이전트를 사용하고, 주 에이전트가 수정과 진행 관리를 맡는다. 불필요한 추가 에이전트는 만들지 않는다. 이 스킬의 검수 작업은 해당 역할 분리를 요청한다.
- 별도 에이전트를 사용할 수 없으면 그 제약을 알린다. 단일 에이전트의 예비 검토는 가능하지만 독립 검수를 완료했다고 보고하지 않는다.

## 1. 대상과 평가 기준 선택

실제 결과물, 요구사항, 기존 프로젝트 지침을 먼저 확인한다. 매체·목적·대상 사용자·사용 환경·유지할 브랜드/기능을 파악한다. 사용자의 “답답하다”, “정신없다” 같은 표현은 검증할 가설로 바꾸고 결함으로 단정하지 않는다.

항상 [공통 기준](references/core.md)을 읽고, 해당 매체의 기준만 추가로 읽는다.

- 웹페이지·앱: [웹 UI 기준](references/web.md)
- 포스터·배너·카드뉴스·정적 시각화: [정적 그래픽 기준](references/graphic.md)
- 영상·쇼츠·모션그래픽: [영상·모션 기준](references/motion.md)

복합 결과물은 필요한 기준을 함께 사용하되 동일한 결함을 여러 항목에 중복 감점하지 않는다. 지원 범위 밖 매체는 평가 가능 범위를 먼저 밝히고, 지원했다고 가장하지 않는다.

적용 항목과 확인할 화면·상태·파일을 짧게 알리고 바로 시작한다. 매번 평가표 승인을 요구하지 않는다. 각 기준의 목적별 보정은 기존 질문을 구체화하는 데 사용하고, 별도 점수 항목이나 가중치를 추가하지 않는다. 목적을 결정할 핵심 정보가 없을 때만 질문한다.

최초 검사 전에 항목 ID, 관찰 질문, 필수 검증, 제외 사유를 고정한다. 해당 없음은 `N/A`로 표시한다. 검사 불가능은 `UNVERIFIED`이며 N/A로 제외하지 않는다. 검사 뒤 불리한 항목을 빼거나 기준을 낮추지 않는다. 사용자가 목적·범위를 바꾸면 변경을 기록하고 새 기준으로 베이스라인을 다시 평가한다.

## 2. 독립 검수

검수 에이전트에 다음 내용을 전달한다. 결과물을 직접 확인할 수 있는 경로나 접근 가능한 증거를 반드시 제공한다.

> 당신은 제작과 분리된 검수 담당입니다. 파일을 수정하지 마세요. 사용자 목적·보존 조건과 선정된 평가 항목을 기준으로 실제 결과물을 확인하세요. 각 항목을 10점 만점 정수로 채점하고, 증거 위치·관찰 사실·문제의 영향·개선 방향을 제시하세요. 확인하지 못한 항목은 점수 없이 UNVERIFIED로 남기세요. 제작자의 설명이나 이전 점수를 정답으로 삼지 마세요. 통과 점수에 맞추어 채점하지 마세요. 주요 문제와 회귀 여부를 확인하세요.

함께 넘길 정보: 사용자 목적·대상 사용자·보존 조건, 대상 버전과 접근 경로, 목적별 보정을 포함해 확정한 평가표(ID·관찰 질문·필수 검증·N/A 사유), 이 스킬과 관련 참조 파일의 절대 경로, 확인 수단, 기존 문제 ID와 수정 내역(재검수 시). 참조 파일의 상대 경로는 이 SKILL.md가 있는 폴더를 기준으로 해석한다. 대화나 스킬 내용이 자동 상속된다고 가정하지 말고 필요한 맥락을 명시적으로 전달한다. 접근 권한이나 도구가 부족하면 그 한계를 반환하게 한다.

재검수는 기존 검수 에이전트를 이어 쓰는 것을 기본으로 한다. 사용할 수 없으면 같은 평가표와 증거·수정 내역을 새 검수자에게 전달한다. 검수자의 수정 금지는 역할 지침이며 기술적 권한 차단을 보장하는 설정은 아니다.

코드나 제작 설명만으로 시각 품질을 판정하지 않는다. 웹은 실제 렌더링과 주요 흐름, 그래픽은 최종 이미지, 영상은 시간 흐름과 필요한 오디오를 확인한다. 정지 프레임만으로 모션·싱크를 검증했다고 주장하지 않는다.

## 3. 채점과 판정

- 모든 적용 항목이 **8/10 이상**이어야 한다. 평균과 가중치는 사용하지 않는다.
- 공통 척도: 0~4점은 핵심 목적 훼손, 5~6점은 큰 개선 필요, 7점은 명확한 결함 존재, 8점은 목적에 충분하고 주요 결함 없음, 9점은 정교하고 일관됨, 10점은 관찰한 범위에서 특별히 뛰어남이다. 구체적인 7·8·9점 기준은 참조 파일을 따른다.
- 세부 질문은 증거 수집용이다. 질문마다 점수를 매기거나 모두 8점을 강제하지 않는다. 다만 주요 결함을 항목 내 다른 장점으로 상쇄하지 않는다.
- P0: 핵심 목적 불가능, 필수 정보 오류, 중대한 오작동. P1: 주요 과업·이해·가독성을 방해하는 결함. P2: 제한적인 마감 문제. 심각도는 사용자 영향에 따라 정하며 취향 차이는 결함으로 단정하지 않는다.
- 미해결 P0/P1이 있으면 PASS 불가. 관련 항목은 8점 이상으로 채점하지 않는다. 실패가 관찰되지 않은 추정만으로 P0/P1을 확정하지 않는다. 심각도는 원인이 아니라 관찰된 영향으로 정한다.
- 필수 증거가 부족한 항목의 점수는 `— (UNVERIFIED)`이다. 일부 확인된 사실과 미확인 검사를 따로 적는다.
- 원인이 불명확해도 관찰된 실패와 영향이 확인되면 결함으로 평가한다. 실패 여부 자체를 판단할 필수 검증이 미완료라면 UNVERIFIED로 남긴다. 필요한 검증을 완료했고 실패 증거가 없다면 의심만으로 감점하거나 통과를 막지 않는다.
- 종료 상태 우선순위: 확인된 미해결 P0가 있으면 `FAIL`; 그 외 미달·P1·필수 미검증 또는 독립 검수 미완료가 있으면 `INCOMPLETE`; 나머지는 `PASS`.

이는 운영용 휴리스틱 평가이며 업계 인증이나 AI 생성 확률이 아니다. 접근성·성능·호환성은 실제 검사한 환경과 범위만 보고한다.

## 4. 수정과 재검수

수정 전 현재 결과물 버전과 작업트리 상태를 기록한다. 기존 버전 관리나 필요한 산출물 사본을 이용해 스킬이 만든 변경을 식별할 수 있게 한다. 무관한 사용자 변경을 복원·삭제하지 않는다.

P0 → P1 → 미달 항목 순으로 영향·비용·회귀 위험을 고려해 수정한다. 이미 통과한 디자인과 핵심 기능은 보존한다. 점수 상승보다 특정 결함 해결을 목표로 한다. 통과한 결과물에 장식 변경을 계속하지 않는다.

1회는 **수정 → 실제 출력 확인 → 독립 재검수**이다. 최초 검수는 0회다. 매번 모든 적용 항목을 같은 기준으로 확인한다. 기존 증거의 재사용 범위는 수정 내역과 영향 범위를 확인한 검수 에이전트가 판단하며, 직접 바꾸지 않은 부분도 공통 스타일·자산·로직의 영향을 받을 수 있다. 문제 ID별 해결 여부 역시 검수자가 실제 결과로 확인한다. 새 필수 검증을 실행하지 못하면 완료로 처리하지 않는다.

회귀는 수정으로 인해 이전에 확인된 기능·정보 전달·시각 품질이 나빠지거나 새 결함이 생긴 경우다. 점수 차이만으로 회귀를 단정하지 않는다. 회귀가 생기면 해당 변경을 고치거나 자신이 만든 변경만 안전하게 철회한다. 마지막 수정본이 무조건 최종본은 아니다. 최종으로 남긴 버전과 보고서의 증거가 반드시 일치해야 한다.

3회 이후 연장은 미달 문제에 대해 아직 시도하지 않은 구체적 수정안과 재검증 수단이 있고, 아래 중단 조건에 해당하지 않을 때만 진행한다.

다음 중 하나면 종료한다.

- 합격 조건 달성
- 최대 5회(또는 사용자 한도) 도달
- 최근 2회 연속 실제 결함 해결 없이 정체: 점수 변화만으로 판단하지 않음
- 검증 수단·수정 권한·필수 자산 부족으로 유효한 다음 수정이 없음

검수만 모드는 최초 평가에서 종료하며 개선 반복을 실행하지 않는다. 중단 사유와 남은 일을 보고하고 추가 반복이나 범위 확대를 임의로 하지 않는다.

## 5. 결과 보고

간결하게 다음을 전달한다. 사용자가 요청하지 않으면 별도 JSON이나 보고서 파일을 만들지 않는다.

1. 최종 상태, 결과물 버전, 검사 환경, 독립 검수 여부, 수정 반복 횟수
2. `항목 | 최초 점수 | 최종 점수 | 핵심 근거` 표 (검수만이면 현재 점수만)
3. 주요 해결 사항과 남은 문제: `ID / 심각도 / 위치 / 관찰 사실과 영향 / 개선 방향 / 재검증 방법`
4. 미검증 항목·이유와 종료 사유

위치는 화면 크기+화면/요소, 이미지 영역, 영상 타임코드 등으로 재확인 가능하게 쓴다. 스크린샷·파일·검사 결과가 있으면 연결한다. “위계가 나쁨” 대신 “보조 문구가 제목보다 커서 핵심 메시지를 찾기 어렵습니다”처럼 설명한다.
