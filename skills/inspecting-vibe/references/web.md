# 웹 UI 기준

공통 기준과 함께 사용한다. 실제 지원 화면 크기와 주요 과업을 선정한다. 지정이 없다면 모바일·데스크톱 대표 크기를 사용하고 정확한 뷰포트를 보고한다. 스크린샷만 제공되면 기능 관련 항목은 UNVERIFIED로 남긴다.

| ID·항목 | 관찰 질문 | 7점 | 8점 | 9점 |
|---|---|---|---|---|
| W1 직관성·탐색·과업 흐름 | 조작 가능한 요소의 단서(어포던스), 이름, 현재 위치, 다음 행동이 분명한가? | 핵심 버튼 의미나 다음 단계가 모호하고 불필요한 왕복 발생 | 주요 과업을 예상 가능한 순서로 수행하고 위치·다음 행동을 알 수 있음 | 복잡한 과업에도 명확한 안내와 효율적인 경로 제공 |
| W2 반응형·접근성 | 화면 크기·확대 시 내용이 유지되는가? 키보드, 포커스, 이름·레이블, 대비로 접근 가능한가? | 주요 내용 잘림, 포커스 식별 어려움 등 확인된 사용 장벽 존재 | 합의한 화면·입력 방식·접근성 검사에서 주요 장벽 없음 | 경계 크기·긴 내용·오류 상황에서도 읽기와 조작이 안정적임 |
| W3 상호작용·상태·복구 | 클릭·입력 결과를 알 수 있는가? 로딩·빈 상태·오류·성공과 재시도가 적절한가? | 눌렀는지 알 수 없거나 오류 원인·복구 방법이 불명확함 | 적용되는 상태마다 피드백이 있고 주요 흐름과 복구가 작동함 | 중복 조작·느린 응답 등에서도 내용과 조작 상태가 명료함 |
| W4 실행 품질 | 주요 흐름에서 런타임 오류, 깨진 자산, 큰 레이아웃 이동·지연이 있는가? 지원 환경에서 작동하는가? | 재현 가능한 오류·지연이 주요 사용을 방해함 | 실제 확인한 환경·흐름에서 방해되는 오류 없고 합의한 성능 기준 충족 | 경계 조건에서도 안정적이며 측정 증거로 품질을 설명할 수 있음 |

## 필수 증거 선정

- 대표 화면과 주요 CTA·메뉴·폼의 실제 동작, 적용되는 로딩·빈 상태·오류 상태를 검사 목록으로 고정한다. 상태가 없는 정적 페이지에 불필요한 상태 처리를 추가하지 않는다.
- 키보드 순서·포커스·컨트롤 이름 등 실제 검사 가능한 접근성 항목을 명시한다. 일부 자동 검사 통과를 전체 WCAG 준수로 확대하지 않는다.
- 콘솔·네트워크 오류는 프로젝트 문제인지 외부/환경 문제인지 구분한다. 수치 성능 목표는 기존 프로젝트 기준이 있으면 사용한다. 측정 없이 성능 점수를 지어내지 않는다.
- 구매·발송·삭제 같은 실제 효과가 있는 흐름은 허용된 테스트 환경이나 안전한 확인 단계까지 검사한다. 권한 없는 실제 실행은 하지 않고 그 구간을 미검증으로 남긴다.

## 목적별 질문 보정

- 랜딩: C1에서 가치 제안·근거, C2/W1에서 주요 CTA의 발견성과 다음 단계를 본다. 화면만으로 전환율을 예측하지 않는다.
- 커머스: W1에서 상품 발견·비교·구매, W3에서 옵션·품절·실패 복구를 본다.
- 대시보드: C2에서 정보 밀도·단위·비교 기준, W1/W3에서 필터·조회 상태를 본다. 장식적 단순화를 위해 필요한 데이터를 없애지 않는다.
- 포트폴리오: C1/C5에서 실제 작업물과 기여 설명, C2에서 사례의 읽는 순서를 본다.
