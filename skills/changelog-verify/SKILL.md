# changelog-verify — CHANGELOG 갱신분 누락 검증·보강

## 경로 선택 (첫 실행 포함)

- 설치할 때 `install.py --target-root`로 작업 폴더를 저장할 수 있다.
- 실행 요청에 작업 폴더가 있으면 그 경로를 우선한다. 없으면 설치된
  `changelog-update/target-root.txt`를 읽는다. 둘 다 없으면 사용자에게 경로를 묻는다.
- 경로는 실제 존재하는 디렉터리인지 확인하고 실행 전에 사용자에게 표시한다.
- 출력은 항상 `<작업 폴더>/changelog/`, 백업·로그는 `<작업 폴더>/.changelog-backups/`다.
  다른 위치에 기록하려면 그 상위 폴더를 작업 폴더로 지정한다.
- 아래 `<작업 폴더>`와 `<스킬 설치 폴더>`는 설명용 표기다. 명령 실행 전 실제 경로로
  치환하고 공백이 있는 경로는 반드시 인용한다. 설치 위치는 현재 SKILL.md 기준으로 찾는다.
- 최초 실행에 changelog 폴더가 없으면 수동 실행에서 생성한다. 기준 스탬프가 없으면
  전체 파일을 대상으로 삼는다. `.last-run`은 실제 반영·검증 성공 후에만 갱신한다.



`changelog-update`가 쓴 갱신분을 **다른 눈으로 다시 본다.** 같은 세션이 자기 글을 검사하면
그냥 통과시킨다(2026-08-13에 실제로 그랬다 — 규약을 세 군데서 강조했는데도 파일 목록만 적었고,
결국 사람이 "더 디테일하게"라고 해서야 고쳐졌다). 이 스킬은 **그 두 번째 시선을 자동화한 것**이다.

## 언제 쓰나

- `cron-run.sh`의 2차 패스 (1차 갱신 직후, 대상 15건 이상인 날만)
- "changelog 검증해줘" / "빠진 거 없나 봐줘"
- 사람이 1차 갱신 결과가 얕다고 느낄 때

## 절대 하지 말 것

`changelog-update`의 「절대 하지 말 것」이 **그대로 적용된다.** 요약하면:

- 🚨 **`changelog/` 안의 일별 파일·부가자료.md 외 어떤 파일도 만들거나 고치거나 지우지 말 것.**
  `changelog/CHANGELOG.md`는 동결 아카이브다 — 읽기만 한다(cron-run.sh가 md5로 감시).
- 🚨 **기존 내용을 삭제하거나 다시 쓰지 말 것.** 이 스킬은 **보강만** 한다.
  1차 패스가 쓴 문장을 "더 잘 쓰겠다"고 재작성하지 않는다. **빠진 것을 덧붙인다.**
  (문장 하나를 통째로 바꿔야 할 유일한 경우는 그 문장이 **틀렸을** 때다. 그때도
  틀린 내용을 지우지 말고 정정 사실을 함께 남긴다.)
- 🚨 `.env`·API 키·토큰·계정 자격증명 열람 금지. 값은 **존재만** 기록.
- 🚨 git 쓰기·배포·운영 DB 쓰기·외부 전송 금지. 조회만.
- 🚨 `mcp-tracking/` 관련은 이메일·user_id 없이 익명 패턴만.
- 🚨 **추정 금지.** 원본에 없는 수치를 채워 넣지 않는다. 없으면 없다고 적는다.

## 절차

### 1. 기계 검사 결과 **읽기** (실행하지 말 것)

🚨 **무인 실행에서는 이 스크립트를 직접 돌리지 마라. `cron-run.sh`가 이미 돌려 놨다.**
`Read`로 오늘 로그를 열어 `=== changelog-verify 기계 검사` 블록을 찾는다.

```
<작업 폴더>/.changelog-backups/cron-<오늘날짜>.log
```

이 스킬의 허용 도구는 `Read`·`Edit`·`Glob`·`Grep`뿐이다. 스크립트를 실행하려 하면
승인 프롬프트가 뜨고, `-p` 모드에는 답할 사람이 없어 **그 자리에서 검증이 끝난다.**
(2026-08-14 첫 시험이 실제로 그랬다 — "사용자 승인이 필요한 명령이라 자동 실행이
막혔습니다. 스크립트를 실행해도 될까요?"만 남기고 종료. → `changelog-update` 지뢰 ⑧과 동일)

로그에 그 블록이 없으면 기계 검사는 **건너뛴다.** 그것 때문에 멈추지 말고 2단계로 간다.
2단계(원본 대조)가 이 스킬의 본체이고, 기계 검사는 보조다.

> 수동 실행(사람이 세션에서 `/changelog-verify`를 부른 경우)에서는 직접 돌려도 된다.
> 그때는 승인해 줄 사람이 있다.
>
> ```bash
> # 일별 분리(2026-08-21) 후에는 전/후를 각각 이어 붙여 비교한다.
> cd "<작업 폴더>"
> cat <1차 패스 직전 백업 폴더>/*.md > /tmp/pre.md
> cat changelog/*.md > /tmp/post.md
> "<스킬 설치 폴더>/changelog-verify/scripts/check-detail.sh" /tmp/post.md /tmp/pre.md "$PWD"
> ```

세 가지만 본다 — ① 폴더를 인벤토리로만 적은 항목 ② "확인 필요"로 위장한 미독
③ 대상 파일인데 CHANGELOG에 흔적이 없는 것. **형식 검사이므로 통과했다고 내용이
충분한 것은 아니다.** 위반이 0건이어도 2단계는 반드시 수행한다.

### 2. 원본 대조 — 이 스킬의 본체

기계 검사가 지목한 항목과, **추가된 텍스트에서 근거 파일이 명시된 항목**을 골라
해당 원본을 열고 대조한다. 순서는 값이 큰 것부터:

1. **기계 검사 ③ 미언급 파일** — 아예 빠진 작업이 있는지. 가장 큰 누락이다.
2. **기계 검사 ② 미독 위장** — 그 파일을 지금 나눠 읽고 채운다. 크기는 사유가 아니다.
3. **기계 검사 ① 인벤토리 항목** — 그 폴더의 문서를 열어 결과·수치·판정을 채운다.
4. **"제작 과정"·"진행 기록"·"작업 로그" 류 문서** — 1차 패스가 결과만 적고
   **실패·재시도 표, 결론 변천, 뒤집힌 가정**을 빠뜨렸는지 확인한다. 가장 잘 누락된다.
5. **회차별 문서**(`result2.md`·`result4.md`, `1차`·`2차`) — 회차별 차이가 적혔는지.

각 항목에서 아래가 원본에 있는데 CHANGELOG에 없으면 **누락**이다:

- 수치와 단위(건수·비율·ms·바이트·행 수), 전후 비교값
- 식별자(PR 번호·커밋 SHA·브랜치·도구명·테이블·필드·파일 경로·Version ID)
- 판정 결과(통과/미달/보류/재현/미재현)와 **그 판정을 뒤집은 근거**
- 실패·재시도·오중단·폴백·환경 미설치
- 원본이 스스로 밝힌 한계("측정 불가", "추정하지 않음", "표본이 작다")

### 3. 보강

누락을 찾으면 **해당 항목에 덧붙인다.** 기존 문장은 남긴다.

- 새 불릿을 추가하거나, 기존 불릿 끝에 문장을 잇는다.
- 서술 기준은 `changelog-update` SKILL.md의 「서술 규약」·「판단 규칙」을 그대로 따른다.
- 근거 등급(A/B/C)도 그대로 적용한다. **원본에 없으면 채우지 않는다.**
- 보강할 것이 없으면 **아무것도 고치지 않는다.** 그것도 정상 종료다.

### 4. 보고

문서 맨 위 인용 블록에 한 줄 남긴다 — 검증 사실, 보강 항목 수, 보강하지 않은 이유.
예: `2026-08-13 22:1x: 2차 검증 패스 — 기계 검사 3건 지목, 원본 대조로 누락 5건 보강(…). 미언급 2건은 원본에 근거 없어 미보강.`

사용자(또는 로그)에게는 **무엇을 보강했고 무엇을 그대로 뒀는지** 보고한다.
"검증 통과"만 적지 않는다 — 무엇을 대조했는지 함께 적는다.

## 판단 규칙

`changelog-update` SKILL.md의 「판단 규칙 — 근거 등급」과 「금지 문장 패턴」을 그대로 쓴다.
이 스킬에만 해당하는 규칙:

- **1차 패스를 깎아내리는 서술을 CHANGELOG에 쓰지 않는다.** 기록의 독자는 작업 내용을
  되짚으려는 사람이고, 누가 무엇을 놓쳤는지는 관심사가 아니다. 보강 내용만 적는다.
- **의심스러우면 원본을 연다.** 1차 패스의 요약이 맞는지 기억이나 추론으로 판정하지 않는다.
- **1차 패스가 "미독 — 다음 실행에서 반영 필요"로 넘긴 것은 이 패스의 최우선 대상이다.**
- 보강이 1차 분량을 넘어도 괜찮다. **분량이 아니라 누락이 결함이다.**

## 지뢰

1. **자기 글을 자기가 검사하면 통과시킨다.** 이 스킬이 존재하는 이유다. 1차 패스와 같은
   세션에서 돌리면 의미가 없다 — `cron-run.sh`는 별도 `claude -p` 프로세스로 띄운다.
2. **기계 검사 통과를 "검증 완료"로 착각하지 말 것.** 형식 3종만 본다. 실제 누락은
   원본 대조로만 나온다.
3. **보강하려고 기존 문장을 재작성하지 말 것.** 과거 기록은 그때의 판단을 담고 있다.
4. **무인 실행에서 승인이 필요한 명령을 부르지 말 것** — 물어보는 순간 그 실행이 죽는다
   (`changelog-update` 지뢰 ⑧과 동일). 허용 도구는 `Read`·`Edit`·`Glob`·`Grep`과
   지정된 스크립트뿐이다.
5. 새 문제가 발견되면 사용자에게 보고한다. 실행 중 스킬 파일을 수정하지 않는다.
