# 내용 파일(doc.json) 쓰기

PDF, 카드, PPT가 같은 내용 파일을 쓴다. 내용은 **표지 정보(meta) + 섹션(sections) + 블록(blocks)**이다. 예시: `assets/examples/showcase.json`(모든 블록), `assets/examples/prompt-kit.json`(프롬프트 공유 자료).

## 목차
1. 구조
2. 블록
3. 내용을 블록으로 나누는 법
4. 원문 발췌와 생략 표시
5. 원본 대조(사실 확인)
6. 문체와 길이
7. 공유 문서에 넣지 않을 것

## 1. 구조

```json
{
  "meta": {
    "kicker": "PROMPT KIT", "issue": "01", "date": "2026.11",
    "title": ["표지 제목 1줄", "2줄"], "subtitle": "무엇을 다루는 자료인지 한 줄",
    "facts": [["tools", "Claude Code"], ["steps", "4단계"]],
    "cta": "저장해 두고 다음 작업에 꺼내 쓰세요."
  },
  "sections": [
    { "title": "섹션 제목", "tag": "PROCESS", "blocks": [ { "type": "text", "text": "…" } ] }
  ]
}
```

| meta 필드 | 필수 | 내용 |
|---|---|---|
| `title` | ○ | 1~3줄 배열. 줄당 13자 이하 권장. Terminal은 마지막 줄이 금색 |
| `kicker`, `issue` | | 시리즈 이름(영문 대문자 권장)과 호수. 호수가 숫자면 Mosaic 표지에 픽셀 숫자 |
| `date`, `subtitle` | | 날짜(`2026.11`), 부제 한 줄 |
| `facts` | | 표지 메타 `[이름, 값]` 3개까지 |
| `cta`, `ctaLabel` | | 마무리 문장과 라벨(기본 `SAVE THIS`) |
| `closing` | | `false`면 마무리 장을 만들지 않는다 |
| `command` | | Terminal 표지 명령줄(기본 `open <kicker>-<issue>`) |
| `sources` | | 대조한 원본 경로(렌더하지 않음, 기록용). 상대 경로로 |

| section 필드 | 내용 |
|---|---|
| `title` ○ | 섹션 제목(20자 이하 권장). 페이지가 넘어가면 "(계속)" 또는 PPT에서 "(1/2)"가 붙는다 |
| `tag` | 오른쪽 작은 라벨(영문 대문자 권장, 예: PROCESS, PROMPT) |
| `newPage` | `true`면 새 페이지, `false`면 이어서. 기본: A4는 이어서, PPT는 섹션마다 새 장, 카드는 새 장(앞 장이 절반 넘게 비어 있으면 이어서) |
| `speaker` | PPT 발표자 노트(선택). 그 섹션 첫 슬라이드의 노트에 들어간다. PDF·카드에는 나오지 않는다. 원본에 없는 사실은 노트에도 쓰지 않는다 |
| `blocks` ○ | 블록 배열 |

브랜드(이름·핸들·태그라인)는 내용 파일이 아니라 `assets/brand.json`에 있다.

## 2. 블록

| type | 필드 | 쓰임 | 페이지 나눔 |
|---|---|---|---|
| `text` | `text`(빈 줄로 문단 구분) | 설명 문단 | 문단 단위 |
| `list` | `items`[문자열], `ordered` | 나열 | 8개 이하는 함께, 넘으면 항목 단위 |
| `callout` | `title`, `text`, `label`(Terminal 라벨) | 꼭 볼 한 가지 | 나누지 않음 |
| `quote` | `text`, `cite` | 인용·원칙 한 문장 | 나누지 않음 |
| `stats` | `items`[{`value`, `label`, `note`, `ratio`(0~1) 또는 `cells`(0~50 정수)}], `unit`(`cells`의 한 칸 뜻) | 큰 숫자 2~4개 | 함께 |
| `steps` | `items`[{`no`, `title`, `sub`, `text`, `rows`[[라벨, 내용]]}] | 단계·과정 | 카드 단위 |
| `points` | `items`[{`title`, `text`}] | 번호 붙은 요점·정리 | 항목 단위 |
| `table` | `head`[], `rows`[[]] | 비교·목록 | 8행 이하는 함께, 넘으면 행 단위(머리 반복) |
| `code` | `body`, `file`, `excerpt`, `notes`[{`mark`, `title`, `text`}] | 복사해 쓰는 코드·프롬프트 | 16줄 이하는 함께, 넘으면 줄 단위. 해설은 뒤에 |

- `stats.value`는 7자 이하(예: `2/3`, `48%`, `12분`). 값은 항상 한 줄로 그리고, 카드보다 길면 같은 블록(PPT는 같은 줄)의 값을 함께 줄인다. 그래도 안 들어가면 넘침 경고가 난다. `ratio`를 주면 미터·진행 칸이 붙는다. 값과 비율은 원본 수치에서만.
- 칸 막대(선택): 같은 단위로 잰 값 여러 개를 비교할 때 항목마다 `cells`(칸 수)를, 블록에 `unit`(예: `"1칸 = 10초"`)을 준다. 한 줄 10칸이고, 같은 블록의 막대는 가장 긴 막대에 맞춘 같은 틀을 쓴다. 칸 수는 원본 수치를 한 칸 크기로 나눠 반올림하고, 정확한 값은 `value`에 쓴다. 50칸을 넘으면 한 칸 크기를 키운다. 한 항목에 `ratio`와 함께 쓰지 않는다.
  ```json
  {"type": "stats", "unit": "1칸 = 10초", "items": [
    {"value": "2분 10초", "label": "도구 A", "cells": 13},
    {"value": "4분 30초", "label": "도구 B", "cells": 27}]}
  ```
- `steps.rows`는 `[["stop", "멈추는 조건"], ["out", "산출물"]]`처럼 짧은 라벨과 내용. 라벨은 영문 소문자 한 낱말 권장.
- `code.body`의 `[빈칸]`, `` `코드` ``, `## 소제목`, `··· 생략:` 줄, 해설 번호 `①~⑨`는 렌더러가 표시를 바꾼다(4절).

## 3. 내용을 블록으로 나누는 법

- 한 섹션 = 한 메시지. 카드(4:5)에서는 섹션 하나가 보통 1~2장이다.
- 원본에 단계가 있으면 `steps`, 수치 결과가 있으면 `stats`, 비교는 `table`, 마무리 교훈은 `points`.
- 블록 종류를 한 섹션에 너무 많이 쌓지 않는다. 강조(callout·stats·quote)는 한 섹션에 하나.
- 짧은 코드·프롬프트 여러 개는 한 섹션에 이어 놓아도 된다(A4는 같은 페이지에 모인다).
- 인스타 카드: 1장에 들어갈 분량을 생각한다. 20장을 넘으면 게시물을 나눈다(빌드가 경고).

## 4. 원문 발췌와 생략 표시

독자는 코드·프롬프트를 복사해 그대로 쓴다. `code.body`는 **요약하지 말고 원문 문장을 그대로** 옮긴다.

- 지면 때문에 빼는 부분은 그 자리에 `··· 생략: <무엇을 뺐는지>` 줄을 둔다(작은 회색 글자로 구분된다).
- 원문 전체를 실으면 `"excerpt": false`. 그 외는 "원문 발췌"로 표시된다.
- 빈칸 `[ ... ]`, 마크다운 `` `...` ``, `## 제목`은 원문 그대로 둔다.
- 해설 번호 `①②③`를 해당 줄 끝에 붙이고, 같은 번호의 `notes`를 쓴다(검사기가 짝을 확인한다). 해설은 "왜 이 문장을 이렇게 썼는지"를 설명한다.
- 원문의 개인 경로·이메일 줄은 생략 줄로 바꾼다(예: `··· 생략: 작업 폴더 경로 한 줄`). 경로를 참조하는 변수 줄(`$CLAUDE_MODS/...`)은 그대로 둔다.
- 남길 줄을 고르는 기준: 사람이 정할 빈칸, 멈추는 조건, 하지 말 것(범위), 산출물 형식.

## 5. 원본 대조(사실 확인)

공유 자료는 공개 게시물이다. 사실과 다른 문장은 디자인 결함보다 크다.

- 단계 이름, 판정 용어, 개수, 조건 문장은 원본 표현을 쓴다(예: 원본이 "불합격"이면 "불통과"로 바꾸지 않는다).
- 멈추는 조건, 버전, 완료 여부, 수치는 원본에서 확인한 것만. 완료를 확인하지 못했으면 "만든"이 아니라 "만드는".
- `points`·`callout`처럼 일반화한 문장은 원본 조건과 반대가 되지 않는지 문장마다 다시 대조한다.
- 원본에 없는 해석·연출(예: 실제로 없는 명령줄, 지어낸 후기)을 사실처럼 쓰지 않는다. 표지 `command`도 실제 의미가 있는 짧은 문구로.
- 도구·제품 설명은 근거가 있을 때만 쓰고, 보고할 때 사용자 확인을 요청한다.

## 6. 문체와 길이

- 저자의 설명(`text`, `notes`, `callout`)은 "-습니다", 규칙·지시를 옮긴 것(`steps` 내용, `points`)은 "-한다"로 통일한다.
- 표지 제목 줄당 13자, 섹션 제목 20자, 단계 제목 14자 이하 권장(검사기가 경고).
- 본문 문장에서 `.` 바로 뒤에 `~`나 백틱을 두지 않는다. PDF 복사 시 줄이 갈라진다. `설정(~/.config)은`처럼 괄호 안에 넣는다(검사기가 경고).

## 7. 공유 문서에 넣지 않을 것

- 로컬 경로(`/Users/...`), 이메일, 키·토큰 형식 문자열. 검사기가 오류로 막는다. 예시 값이 필요하면 `~/projects/...`처럼 일반화한다.
- 회사 내부 자료, 고객 정보, 미공개 계획. 원본이 업무 자료라면 사용자에게 공개 범위를 확인한다.
