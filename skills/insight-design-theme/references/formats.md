## 1. 준비(승인이 필요한 것)

| 무엇 | 언제 | 방법 |
|---|---|---|
| Google Chrome | 항상(렌더·인쇄·PPT 그래픽) | 다른 경로면 `CHROME` 환경변수 |
| 웹 글꼴 | 처음 한 번(스킬을 갱신한 뒤에도 한 번) | `python3 -I scripts/fetch_fonts.py` → 스킬 폴더 `assets/fonts/web/`에만 저장, 검증값(sha256) 확인, 코드 글꼴의 복사 보정본(`*-CopySafe.ttf`)을 만든다(5절). 인터넷 필요 |
| pptxgenjs | PPT만 | 없으면 빌드가 멈추고 명령을 알려 준다. **사용자 승인 후** `npm ci --prefix assets/ppt`(스킬 폴더 안, 버전 고정) |
| 데스크톱 글꼴 | PPT만 | PPT는 글꼴을 파일에 넣지 못해 여는 컴퓨터에 설치돼 있어야 한다. `fetch_fonts.py --desktop`으로 `assets/fonts/desktop/`에 받고, **사용자 승인 후** `~/Library/Fonts`에 복사(있는 파일은 덮어쓰지 않음). 설치 후 PowerPoint 재시작. 승인이 없으면 `ALLOW_MISSING_FONTS=1`로 대체 글꼴 빌드만(시안과 다르다고 알린다) |
| Microsoft PowerPoint | PPT 확인(선택) | 실제로 열어 PDF로 내보내 보는 것이 가장 확실한 확인 |

미리보기·복사 검사·PowerPoint 확인은 macOS(PDFKit, Swift, AppleScript) 기준이다. 다른 운영체제에서는 결과 파일만 만든다.

## 2. 빌드

```sh
scripts/build.sh <doc.json> <mosaic|terminal> <pdf|cards|ppt> <출력 폴더> [이름]
```

| 형식 | 결과 |
|---|---|
| `pdf` | `<이름>.pdf`(A4 세로), `preview/<이름>-pN.png`, `preview/<이름>.txt`(복사 텍스트) |
| `cards` | `cards/<이름>-01.png …`(1080×1350, 파일 이름 순서 = 캐러셀 순서), `<이름>-card.pdf`(4:5), `preview/` |
| `ppt` | `<이름>.pptx`, `<이름>.pptx.txt`(슬라이드 텍스트), PowerPoint가 있으면 `<이름>-preview.pdf`와 `preview/<이름>-ppt-pN.png` |

순서: 내용 검사 → 글꼴·의존성 확인 → 렌더 → 결과 파일 → 미리보기 → 검사.
종료 코드: 0 통과, 1 렌더·내보내기 실패, 2 준비 안 됨(메시지대로 준비), **3 넘침 경고**(결과는 만들어 두니 미리보기를 보고 고친다).

## 3. 페이지 나눔과 넘침

**PDF·카드**는 브라우저에서 실제 높이를 잰다(`assets/web/kit.js`). 블록을 하나씩 넣다가 넘치면 블록 안의 항목(문단, 카드, 표 행, 코드 줄) 단위로 다음 페이지에 넘긴다.
- 짧은 묶음(코드 16줄·표 8행·목록 8개 이하, 큰 숫자, 해설)은 나누지 않고, 안 들어가면 통째로 다음 페이지로.
- 섹션 제목이 페이지 끝에 혼자(또는 한 항목과만) 남으면 제목도 다음 페이지로. 코드의 `## 소제목` 줄도 마찬가지.
- 이어지는 페이지 제목에 "(계속)", 코드 창 제목에 "(이어서)".
- 마무리: 마지막 페이지에 자리가 남으면 그 아래에 디더 면(Mosaic) 또는 저장 안내 상자(Terminal), 없으면 마무리 장을 따로.
- **넘침 경고**(종료 코드 3): 한 항목이 한 페이지보다 크면 잘린다. 그 항목을 나눈다(긴 문단은 빈 줄로, 긴 카드는 `text`를 줄이거나 `rows`를 나눔, 긴 코드 줄은 원문이라 그대로 두고 블록을 나눔).
- **좌우 넘침 경고**(종료 코드 3): 글자가 지면 좌우 여백 밖으로 나가 잘리는 경우. 큰 숫자 값이 너무 길면(값을 55%까지 줄여도 안 들어감) 값을 줄이거나 큰 숫자 개수를 줄인다. 표 칸에서 띄어쓰기 없이 30자를 넘는 낱말(주소·경로)은 줄바꿈되게 했다.

**PPT**는 실제 높이를 잴 수 없어 글자 폭으로 줄 수를 어림한다(`assets/ppt/deck.js` `plan`). 넉넉하게 잡아 빈 공간이 생길 수는 있어도 상자 밖으로 넘치지 않게 했다.
- 섹션마다 새 슬라이드. 블록을 위에서 아래로 쌓고, 넘치면 다음 장. 장이 여러 개면 제목에 "(1/2)".
- 단계 카드는 한 장에 4개, 요점은 3개, 큰 숫자는 4개까지(고르게 나눔).
- 코드는 15pt, 줄당 약 0.305in로 잡고 고르게 나눈다. 줄바꿈된 다음 줄은 내어쓴 만큼 좁게 계산한다. 해설은 그 장에 번호가 있는 것만 오른쪽에.
- 큰 숫자 값은 한 줄(줄바꿈 없음)이다. 글꼴의 글자 폭으로 너비를 어림해 카드보다 길면 같은 줄의 값을 함께 줄인다.
- 섹션에 `speaker`가 있으면 그 섹션 첫 장의 발표자 노트에 넣는다(사용자가 발표 원고·노트를 원할 때).
- 미리보기에서 상자 밖으로 넘친 글자가 보이면 해당 블록을 나누거나 줄인다.

## 4. 확인할 것

1. 넘침 경고가 없는지(있으면 3절).
2. `preview/`의 PNG를 **모든 페이지** 직접 본다: 겹침, 잘린 글자, 거의 빈 페이지, 혼자 남은 줄, 표지 제목 줄바꿈.
3. 복사 검사(PDF·카드) 또는 PPT 점검이 "문제 0개"인지.
4. 카드: 20장 이하인지(인스타그램 캐러셀 한도), 첫 장(표지)만 보고도 무엇에 대한 게시물인지 알 수 있는지.
5. 원본 대조는 사람이 할 일이다(`content.md` 5절). 검사기는 사실을 모른다.
6. 더 엄격한 디자인 확인이 필요하면 별도 검수 에이전트(예: `inspecting-vibe` 스킬)를 제안한다.

## 5. 복사 품질 규칙(PDF)

macOS·iOS PDF 텍스트 추출(PDFKit)에서 실제로 확인한 문제들이다. iPhone 사용자가 복사할 때 그대로 겪는다.

- **Pretendard는 정적 굵기 파일**을 쓴다. 가변 글꼴은 Chrome PDF에 Type3로 들어가 복사 순서가 뒤섞였다.
- **코드 본문은 DejaVu Sans Mono의 복사 보정본**. PDFKit은 나란한 두 글자의 세로 범위(글리프 경계 상자)가 겹치지 않으면 그 사이에 줄바꿈을 넣는다. 예: `- .env`·`* .ics`(가운데 `-`·`*`와 바닥 `.`), `- 'a'`, `x-.ics`, `a.~b`, 밑줄(`_`). 보정본은 `fetch_fonts.py`가 원본에서 만들며 글리프 경계 상자 값만 같은 세로 띠로 넓힌다(윤곽선은 그대로라 화면은 원본과 픽셀 단위로 같다). 밑줄은 예전 방식대로 본문 글꼴 글리프로도 그린다(`.code .us`).
- **백틱은 화면에서 뺀다**. `1. \`경로\``처럼 `.` 뒤에 백틱이 오면 줄이 갈라졌다. 인라인 코드 서식(배경색)으로 대신한다.
- **본문 문장에서 `.` 바로 뒤의 `~`·백틱**도 같은 이유로 피한다(검사기 경고).
- **줄번호·해설 번호는 글자가 아니라 그림**. 글자면 복사 텍스트에 섞인다.
- 화면에서 자동 줄바꿈된 자리는 복사 시 줄바꿈이 된다. 마크다운에서는 같은 문단으로 읽혀 붙여 넣기에 지장이 없다. 줄바꿈된 다음 줄의 내어쓰기는 CSS 배치일 뿐이라 복사 텍스트에 공백이 더해지지 않는다.
- 2열 영역(단계 카드, 해설)은 복사 순서가 열을 오간다. 복사가 중요한 코드는 1열이다.

검사(`scripts/check_pdf_text.py`):
- 코드 각 줄이 추출 텍스트에 이어진 채로 있는지(공백·줄바꿈 무시).
- 화면의 한 줄이 추출 텍스트에서도 한 줄 안에 있는지. 렌더러가 코드 블록의 화면 줄 목록을 기록해 넘긴다(`kit.js` `codeRows`). 줄바꿈을 무시하는 앞의 비교로는 "- .env"가 "-\n.env"로 갈라지는 것을 못 잡는다.
- PDF 안(압축 스트림 포함)과 추출 텍스트에 실제 계정 경로·이메일이 없는지.

## 6. PPT 후처리와 PowerPoint 확인

`deck.js`의 후처리(`finish`)가 하는 것과 이유:

- **테마 색**: pptxgenjs는 테마 색을 쓰지 않아 직접 써 넣는다. Terminal은 '텍스트 1'을 밝은 아이보리로 둬서 새로 넣는 글자가 어두운 배경에서 보이게 했다.
- **한글 줄바꿈**: 글자 언어가 en-US면 PowerPoint가 한글을 단어 중간에서 끊는다 → 모든 글자 조각을 ko-KR로. `eaLnBrk="0"`만으로는 해결되지 않았다.
- **고정폭·픽셀 영문 글꼴 속 한글**: PowerPoint가 맑은 고딕·바탕으로 바꾼다 → 동아시아 글꼴을 Pretendard로.
- **그림 대체 텍스트**: pptxgenjs는 원본 PNG의 로컬 전체 경로를 넣는다(계정·폴더명이 공유 파일에 노출) → 설명 문구로.
- **코드 내어쓰기**: pptxgenjs는 기호 없는 문단의 들여쓰기를 0으로 고정한다 → 코드 본문 문단마다 앞 공백·목록 기호 길이만큼 `marL`·`indent`를 넣는다(글자는 그대로).
- **ZIP 폴더 항목 제거**: 클라우드 저장소에서 열기·공동 편집이 실패할 수 있다. 파일만 새 ZIP에 담는다.
- **Terminal 제목 글꼴**: PDF는 Neo둥근모 Pro지만 PowerPoint에서는 글자가 보이지 않는다(UPM 16 글꼴) → Galmuri11.

PowerPoint 확인:
- 여러 작업이 동시에 PowerPoint를 쓰지 않게 잠근다(`$TMPDIR/insight-design-theme-powerpoint.lock`). 파일은 PowerPoint 샌드박스 폴더에 복사해 열어 권한 창이 뜨지 않게 한다.
- 처음 실행할 때 macOS가 "PowerPoint 제어 허용"을 물을 수 있다. 사용자에게 허용을 부탁한다.
- 내보내기가 시간 초과·오류(-9074, "사용자 취소" 등)로 실패하면 PowerPoint에 대화 상자가 떠 있거나 응답이 없는 상태다. **강제 종료하지 않는다.** 사용자에게 대화 상자를 닫거나 PowerPoint를 종료해 달라고 부탁하고, 확인되면 다시 빌드한다. 손으로 고친 pptx는 복구 창을 띄울 수 있으니 항상 생성 스크립트로 만든다.
- pptx 스킬의 `validate.py`가 있으면 `PPTX_VALIDATE=<경로> PY=<lxml·defusedxml 있는 Python 3.10+>`로 추가 검사(선택).

## 7. 공유할 때

- 인스타그램: `cards/`의 PNG를 순서대로 올린다(PDF는 바로 올릴 수 없다). 첫 장이 표지다.
- 내려받는 자료(링크·DM 배포): A4 PDF.
- PPT 원본을 다른 사람에게 보내면 그쪽에도 같은 글꼴이 있어야 한다. 배포용으로는 PowerPoint에서 내보낸 PDF가 안전하다.
- 픽셀 그래픽은 그림이라 PPT 안에서 도형처럼 고칠 수 없다. 바꾸려면 `assets/ppt/assets.html`을 고쳐 다시 빌드한다.

## 8. 문제 해결

| 증상 | 조치 |
|---|---|
| "웹 글꼴이 없습니다" | `python3 -I scripts/fetch_fonts.py`(받은 글꼴이 있으면 복사 보정본만 만든다). 검증값 불일치면 배포처 파일이 바뀐 것이니 사용자에게 알린다 |
| "렌더 실패" | 메시지의 스크립트 오류를 고친다. 내용 파일 JSON 형식 오류, 알 수 없는 블록 종류가 흔하다 |
| 넘침 경고 | 3절 |
| 복사 검사 문제 | "두 줄로 갈라짐"이면 먼저 `fetch_fonts.py --check`로 복사 보정본이 있는지 본다. 코드가 아닌 문장이면 해당 기호 배치를 5절 기준으로 고친다. 코드·프롬프트 원문 자체는 바꾸지 않는다 |
| 페이지가 예상보다 많음 | 긴 코드는 정상. 카드 형식은 섹션마다 새 장이 기본이므로 짧은 섹션을 합치거나 `newPage: false` |
| PPT에 빈 공간이 큼 | 추정이 넉넉해서다. 블록 순서를 바꾸거나 짧은 섹션을 합친다 |
| PowerPoint 내보내기 실패 | 6절. 강제 종료하지 않는다 |
