## Codex 차단 사항

1. 기본 샌드박스에서 CLI의 in-process app-server 초기화가 `Operation not permitted`로 실패했습니다. 허용된 격리 검증을 샌드박스 밖에서 재실행했습니다. 모델의 소스 접근은 계속 read-only로 설정했습니다.
2. 부모 프로젝트에만 정의를 둔 최초 구성에서 중첩 Git 프로젝트의 전용 에이전트 등록을 확인하지 못했습니다. 각 실제 작업 루트에 정의를 설치하고 루트에서 CLI를 시작하도록 검증 구성을 바꿨습니다. Claude에서는 이 구성으로 실제 등록이 확인됐습니다. 동시에 Claude의 `--restricted`도 제거했으므로 최초 등록 실패 원인을 경로 하나로 단정하지 않습니다.
3. Codex의 `--ephemeral` 실행은 자식 호출 시 `no rollout found for thread id` 오류가 났습니다. 또한 작업 식별자에 하이픈을 사용하면 도구가 거부했습니다. 영구 세션으로 바꾸고 작업 식별자에는 밑줄을 쓰도록 했습니다. 원본 등록 이름 `code-reviewer`는 변경하지 않았습니다.
4. 실제 작업 루트의 TOML, 일회성 trusted 설정, `--enable multi_agent`, `agents.enabled=true`를 사용하고 `--disable multi_agent_v2`까지 지정했지만, 기록된 실행 버전은 v2였습니다. 이 호출 환경의 `collaboration.spawn_agent`에는 등록된 에이전트 종류를 선택하는 매개변수가 없었습니다. 부모는 전용 호출 불가로 보고했고 소스 리뷰를 수행하지 않았습니다.

등록 지침을 일반 자식의 메시지에 복사하는 우회는 전용 에이전트 선택 검증과 다르므로 수행하지 않았습니다. 이 결과를 Codex의 모든 버전·모델·실행 환경에 대한 불가 판정으로 확대하지 않습니다. 아직 실패 원인 전체나 다른 환경의 동작을 확인하지 않았습니다.

### 추가 확인: 파일 구조와 호출 인터페이스 구분

사용자 요청에 따라 공통 지침 → Claude Markdown·Codex TOML 생성 구조를 유지한 채 다시 확인했습니다. [공식 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)는 프로젝트 `.codex/agents/`의 TOML과 `name`, `description`, `developer_instructions`를 안내합니다. 현재 생성물은 이 필드를 포함하며 TOML 파싱도 통과했습니다. 이것은 네이티브 호출 성공과 별도의 확인입니다.

- 설치된 CLI의 `codex debug models --bundled`와 현재 계정 모델 목록을 대조했습니다. `gpt-6.1-sol`은 code mode·v2, `gpt-5.6-luna`는 code mode·v1 메타데이터를 사용합니다. 두 실행의 자체 세션 기록에서도 각각 v2·v1을 확인했습니다. 따라서 이전의 문제를 v2 하나만의 문제라고 단정할 수 없습니다.
- 번들 목록에만 있던 `gpt-5.5` 비교 호출은 현재 ChatGPT 계정에서 지원하지 않는다는 오류로 종료했습니다. 리뷰는 수행하지 않았고 계정 목록을 확인한 후 이 모델을 재시도하지 않았습니다.
- v1 모델에서 지연 도구를 실제 검색했습니다. 자체 세션 `01a1aad1-7c59-71e0-b1dc-d58f4ce5e859`의 도구 출력에 있는 `multi_agent_v1__spawn_agent` 선언은 `fork_context`, `items`, `message`, `model`, `reasoning_effort`만 받습니다. `agent_type` 같은 등록 종류 선택 필드는 없습니다. 모델의 최종 설명만이 아니라 도구 선언 원문을 대조했습니다.
- 빈 임시 `CODEX_HOME`, 번들 모델 메타데이터, 인증 없는 localhost 가짜 API로 CLI가 생성하는 요청을 수집했습니다. 서버는 요청 본문만 수집하고 HTTP 400으로 중단했으며 인증 헤더는 수집하지 않았습니다. 외부 모델을 호출하거나 실제 리뷰를 수행한 검증이 아닙니다. 이 요청의 v2 `collaboration.spawn_agent` 스키마도 `task_name`, `message`, `fork_turns`, `model`, `reasoning_effort`만 제공하고 `additionalProperties: false`였습니다. `multi_agent_v2_dynamic_tools`를 일회성으로 켜도 등록 종류 선택 필드는 추가되지 않았습니다. 이 실험 옵션은 제품 설정에 채택하지 않았습니다.
- 이름 결합도 별도로 검사했습니다. 새 임시 프로젝트에 같은 공통 지침을 가진 `name = "code_reviewer"`와 `code_reviewer.toml`을 두고 `task_name = "code_reviewer"`, `fork_turns = "none"`으로 자식을 한 번 호출했습니다. 부모·자식에게 정의 파일 읽기와 지침 복사를 금지하고 주입된 지침의 버전만 묻게 했습니다. 자식은 “버전 없음”으로 응답했습니다. 부모 세션은 `01a1aad5-35a7-7450-b2d8-509e9806b525`, 작업 식별자는 `/root/code_reviewer`입니다. 이름 일치만으로 전용 지침이 자동 적용된다는 것을 확인하지 못했으며, 이를 전용 리뷰어 실행 성공으로 처리하지 않았습니다. 소스 리뷰는 하지 않았습니다.

추가 비교 프로젝트의 4개 파일·Git 상태와 이름 결합 프로젝트의 2개 파일 해시는 전후 동일했습니다. 구조·생성기·제품용 어댑터는 변경하지 않았으며, 일반 자식에게 공통 지침을 전달하는 방식으로 전환하지 않았습니다. 확인된 차단 지점은 **현재 실행 인터페이스의 등록 종류 선택과 지침 적용**입니다. 이것을 공통 지침 생성 구조 자체의 결함으로 해석하지 않습니다. CLI 내부에서 왜 이 인터페이스가 노출되는지까지는 규명하지 못했습니다.

## 남은 검증

- Codex에서 실제 전용 리뷰어 선택과 세 가지 모드의 실행. 현재 환경에서는 차단됨.
