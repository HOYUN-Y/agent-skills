# 세컨드브레인 파일 목록·변경분 갱신·심층 조사 개선안

상태: 설계 원안과 구현 기록. 2026-11-09 작성 당시의 제안을 아래에 보존했다. 현재 구현 범위는 끝의 '구현 결과'와 '감독 검토 결과'를 기준으로 확인한다. 실제 볼트 적용과 자동 실행 설정은 이번 작업에 포함하지 않았다.

## 제안하는 방향

원본을 한 폴더로 모으거나 각 원본 폴더에 `INDEX.md`를 만드는 구조로 바꾸지 않는다. 현재의 `src-*` 원본 연결과 볼트 최상위 안내를 유지하면서, **파일 목록은 스크립트가 관리하고 의미·질문·기준본 연결은 에이전트가 관리한다.**

사용자가 확인할 수 있어야 하는 것은 다음 세 가지다.

- **무엇이 있나:** 어느 자료원·프로젝트·하위 경로에 어떤 파일이 있는가.
- **무엇이 바뀌었나:** 마지막 성공한 목록 조사 이후 추가·변경·삭제 후보가 무엇인가.
- **무슨 질문에 답할 수 있나:** 본문에서 확인한 근거와 변경 이력으로 실제 질문에 답할 수 있는가.

매번 전체 자료를 다시 읽는 작업량을 줄이되, 파일이 존재한다는 사실을 본문 조사 완료로 보고하지 않는다.

## 현재 기능과 확인된 공백

현재도 자동화와 심층 조사 규칙이 있으므로, 새 체계를 따로 만들기보다 기존 구성요소를 확장한다.

| 현재 구성 | 이미 하는 일 | 보완할 부분 |
|---|---|---|
| [SKILL.md](../skills/secondbrain-index-sync/SKILL.md) | 영역·주제·프로젝트 연결, 원본 보호, 비공개 차단, 질문별 검증 | 파일 목록과 의미 색인의 역할·쓰기 권한을 구분하고 일상 갱신 경로를 추가 |
| [check_index.py](../skills/secondbrain-index-sync/scripts/check_index.py) | 안내를 재귀적으로 따라 링크·중복·분할·비공개 위반 검사 | 일반 자료 변경 감지는 최상위와 바로 아래 중심. 더 깊은 파일 단위 변경 이력이 필요 |
| [manifest.py](../skills/secondbrain-index-sync/scripts/manifest.py) | 자료원 아래 `.md`·`.txt`를 재귀 탐색하고 앞부분 발췌 | 임시 발췌이며 지속 목록·변경 이력·조사 이력은 없음. 현재는 텍스트 본문의 주민번호·비밀번호 패턴을 검사하지 않고 발췌를 출력 |
| [doc_manifest.py](../skills/secondbrain-index-sync/scripts/doc_manifest.py) | 지원 문서의 텍스트 추출, 민감정보 후보·일부 실패 구분 | 변환 도구의 종료코드 확인이 없어 비정상 종료가 텍스트 없음으로 기록될 수 있음. PDF 앞 3쪽 등 추출 범위도 별도로 추적할 필요 |
| [build_topics.py](../skills/secondbrain-index-sync/scripts/build_topics.py) | 주제 분류 결과로 하위 색인 초안 생성 | 파일의 의미·프로젝트 상태를 자동 판정하는 도구로 확대하지 않음 |
| [full-reindex.md](../skills/secondbrain-index-sync/references/full-reindex.md) | 내용 기반 재색인, 임시 자료 정리, 검증·통합 | 최초 조사와 이후 변경분 갱신을 연결하는 지속 상태가 필요 |

점검기의 이동 후보 검색은 깨진 링크마다 원본 트리를 다시 순회한다. 빈 폴더 판정도 하위 트리를 순회할 수 있다. 큰 자료원에서는 링크 정합성 검사와 전체 원본 탐색의 비용을 분리할 필요가 있다. 이는 코드에서 확인한 구조이며, 개선 후 성능 수치는 아직 측정하지 않았다.

또한 폴더 수정 시각은 깊은 파일의 내용 변경을 완전하게 나타내지 않는다. “모든 색인 중 가장 오래된 수정 시각”과 비교하는 방식만으로 자료별 최신 반영 여부를 판단하지 않는다.

## 유지할 구조와 추가할 정보

### 원본·파일 목록·의미 색인

| 층 | 저장 위치 제안 | 작성 주체 | 역할 |
|---|---|---|---|
| 원본 | 기존 `src-*`가 가리키는 폴더 | 사용자·원래 작업 도구 | 자료의 실제 내용. 스킬은 읽기 전용 |
| 기계용 파일 목록 | `.secondbrain/inventory.json` | 스크립트 | 경로·형식·크기·수정 시각·자료원 조사 상태 |
| 사람·에이전트용 목록 | 최상위 `catalog.md`, 필요한 `catalog--*.md` | 스크립트 | 자료원·폴더별 파일 탐색과 원문 링크 |
| 의미 색인 | 기존 영역 색인·MOC·프로젝트 안내 | 에이전트 | 용도·질문·경험·결정·기준본 후보·후속 변경 연결 |
| 조사 상태 | `.secondbrain/review-state.json` | 검증 후 감독 세션 | 어떤 원본 상태를 어떤 범위로 읽고 어느 안내에 반영했는지 기록 |

위 경로와 파일명은 **새 규약의 제안**이다. 현재 스킬에 이미 구현된 출력 경로가 아니다. 실제 도입 때 `SKILL.md`의 쓰기 허용 대상도 함께 고쳐야 한다.

자동 목록은 기존 의미 색인 안의 큰 자동 생성 구역으로 섞지 않는다. 생성 파일임을 표시하고, 스크립트가 소유한 목록만 다시 만든다. 수작업 설명은 기존 색인에 남겨 재실행으로 지워지지 않게 한다.

원본 파일이 많으면 목록을 자료원·프로젝트·하위 경로별로 나누고 상위 목록에서 연결한다. 원본 폴더에 안내 파일을 쓰지 않는다. 수작업 안내는 가급적 안정적인 `catalog.md` 또는 자료원 목록을 참조한다.

### 목록의 최소 정보

- 자료원 식별자와 볼트 기준 상대경로. 실제 디스크 표기는 링크 생성용으로 보존한다.
- 형식, 바이트 크기, 파일의 `mtime_ns`.
- 자료원별 조사 상태와 마지막으로 완전하게 목록화한 시점.
- 적용한 비공개·제외 정책의 버전 또는 지문.

NFC 정규화 값은 비교용으로 따로 계산하고, 원래 경로를 정규화 문자열로 덮어쓰지 않는다. 정규화 후 이름이 충돌하면 두 파일을 자동 합치지 않고 충돌로 보고한다.

사람용 목록에는 파일 링크·형식·수정 시각 정도를 우선 보여준다. 원시 데이터·코드·미디어도 목록 범위에 들어간다면 형식별 수와 상세 목록 범위를 명시한다. 의존성·빌드·캐시·설치본 등 제외한 항목을 조용히 “전체 파일”에 포함했다고 보고하지 않는다.

파일 목록에는 본문·개인정보·자격정보를 저장하지 않는다. 비공개 자료는 일반 목록에서 경로와 이름까지 제외하고, 필요한 보류 정보는 기존의 비공개 규칙에 따른다.

## 일상 갱신 절차

```text
비공개·자료원 확인
  → 깊은 경로까지 파일 메타데이터 목록화
  → 이전의 성공한 목록과 비교
  → 파일 목록 갱신 + 변경 후보 보고
  → 해당 원본을 참조하는 안내·프로젝트·질문 추리기
  → 필요한 본문만 추가 조사
  → 의미 색인 보강
  → 링크·질문 검증
  → 조사 상태 기록
```

### 변경 판정과 실패 처리

| 상황 | 처리 |
|---|---|
| 처음 보는 경로 | 추가 후보. 파일 존재와 내용 해석은 별도로 처리 |
| 같은 경로의 크기·수정 시각 변경 | 본문 재확인이 필요한 변경 후보 |
| 이전 경로가 현재 목록에 없음 | 해당 자료원을 완전히 조사했을 때만 삭제 후보 |
| Drive 오프라인·권한 오류·순회 중단 | 자료원 미확인/부분 조사. 이전 항목을 삭제로 바꾸지 않음 |
| 자료원의 연결 대상 변경 | 일반 대량 삭제로 처리하지 않고 자료원 변경으로 보류 |
| 이동으로 보이는 파일 | 이름·위치·기존 근거·필요한 내용 비교로 이동 후보 제시. 파일명 하나만 같다는 이유로 자동 수정하지 않음 |
| 새 비공개 지정 | 기존 목록·발췌·조사 캐시·일반 링크에서도 제외. 비공개 원문을 다시 읽어 확인하지 않음 |

`size + mtime_ns` 비교는 저렴한 변경 후보 탐지다. 같은 메타데이터를 유지한 내용 변경까지 검출한다고 보장하지 않는다. 본문을 추출하거나 재검토할 때 내용 지문과 추출기 버전을 기록하면 조사 근거를 더 정확히 구분할 수 있다. 전체 파일 해시 계산을 일상 갱신의 기본값으로 넣지는 않는다.

목록은 자료원별 성공 여부를 보존한다. 한 자료원이 실패해도 성공한 자료원의 변경 보고는 가능하지만, 실패한 자료원의 오래된 목록은 최신 조사로 표시하지 않는다. 쓰기는 임시 파일 작성·검증 후 교체해 중간 실패로 기준 목록을 잃지 않게 한다.

메타데이터 순회 자체는 기본적으로 전체 대상 파일 수에 비례한다. 처음부터 파일 감시 데몬이나 운영체제별 이벤트 연동을 추가하지 않는다. 우선 줄일 비용은 반복 본문 추출·전체 의미 재조사·깨진 링크별 중복 순회다.

### 무엇을 다시 읽을지 추리기

기존 안내의 링크를 읽어 **원본 경로 → 참조 안내** 관계를 만든다. 변경된 원본과 직접 참조하는 안내를 갱신 후보로 제시하고, 상위 안내는 연결이나 설명이 영향을 받을 때 확인한다. 이 역참조는 링크 파싱으로 계산할 수 있으므로 별도 데이터베이스부터 만들지 않는다.

프로젝트 전체 판단이 바뀔 수 있는 자료는 해당 프로젝트의 기준본·후속 변경·질문 검증을 함께 확인한다. 예를 들어 코드 변경은 구현 상태와 검증 근거에, 계획 변경은 기존 결정·실제 반영 여부에 영향을 줄 수 있다. 영향을 받은 질문을 에이전트가 판단하며 스크립트가 자동으로 확정하지 않는다.

새 자료의 주제가 불명확하면 파일 목록에는 존재를 남기고 의미 연결은 보류할 수 있다. 반대로 중요한 근거가 빠져 질문에 답하지 못한 경우에는 파일 수정이 없어도 심층 조사를 수행한다.

**목록 조사 완료와 의미 검토 완료는 다른 체크포인트다.** 매 실행에서 직전 목록과의 차이뿐 아니라 현재 원본 상태와 마지막 검토 완료 상태를 비교한다. 목록을 저장한 뒤 본문 조사에 실패했어도 그 파일은 다음 실행의 재검토 후보로 남는다. 변경이 없다는 이유로 미완 작업을 건너뛰지 않는다. 이 후보는 목록과 `review-state.json`의 차이로 다시 계산하며 별도 영구 큐 파일부터 추가하지 않는다.

## 심층 조사 규칙 보강

기존 질문별 검증을 유지하면서 다음 범위를 명시한다.

1. 사용자 질문 또는 해당 프로젝트에 맞는 실제 질문을 정한다.
2. 기존 안내를 따라 원문과 관련 하위 자료를 확인한다. README 하나를 읽은 상태와 관련 구현·검증·후속 기록까지 확인한 상태를 구별한다.
3. 서로 다른 자료의 관계와 근거를 기록한다. 날짜·파일명만으로 최신본·완성본·같은 프로젝트라고 단정하지 않는다.
4. 관련 설명을 기존 색인에 보강한다. 흩어진 문서·코드·규칙표를 연결할 필요가 확인된 프로젝트에만 상세 안내를 만든다.
5. 같은 질문으로 다시 탐색해 경로 도달과 답변 충족을 따로 판정한다.

자료별 조사 상태는 최소한 **목록화 / 제목·앞부분 / 관련 본문 / 전문 / 미확인·보류**를 구분한다. “본문 추출 완료”를 “전문을 읽고 검증함”으로 바꾸지 않는다.

내용 판단에는 질문별 근거·기준 시점·읽은 범위·남은 공백을 남긴다. 계획·로컬 구현·시험 결과·운영 반영도 구분한다. 자료가 변경되면 과거 조사 이력을 지우기보다 현재 반영 여부를 미확인으로 전환하고 재검토 대상으로 제시한다.

특정 분야의 검색 축은 해당 자료에서 정한다. 업무 프로젝트는 결정·구현·검증·후속 변경, 리서치는 주장·원문·번역·검증·활용 결과, 지원 자료는 지원처·시기·문항·작성 상태처럼 서로 다른 축을 사용할 수 있다. 모든 자료에 같은 항목을 강제하지 않는다.

## 기존 스킬에서 수정할 곳

| 파일 | 수정 제안 |
|---|---|
| `SKILL.md` 설명·작업 고르기 | “파일 목록 갱신”, “변경된 자료만 반영”, “전반 탐색 보강”을 구별. 목록만 요청하면 본문 해석을 자동 시작하지 않음 |
| `SKILL.md` 절대 규칙 | 자동 목록·기계용 목록·조사 상태의 허용 경로와 쓰기 주체 추가. 원본 보호·비공개 규칙은 유지 |
| `SKILL.md` 현재 구조·변경 감지 | 이전 색인의 최저 수정 시각 대신 파일별 목록 비교와 자료원 성공 상태를 사용 |
| `SKILL.md` 판단·반영 | 자동 목록에서 의미 색인으로 연결하는 단계, 영향을 받은 안내·질문을 추리는 기준 추가 |
| `SKILL.md` 검증·보고 | 목록 수·본문 조사 수·질문 검증 수를 분리. 새 오류와 기존 보류를 구분 |
| `references/full-reindex.md` | 초기 전반 조사에서 기준 목록·조사 상태를 만들고 이후 증분 갱신으로 이어지는 절차 추가 |
| 신규 `references/incremental-sync.md` | 변경 비교·영향 범위·오프라인·실패·미확인 처리의 상세 규칙 |
| 신규 `references/catalog.md` | 자동 목록의 형식·소유권·페이지 분할·수작업 색인과의 연결 규칙 |
| 신규 `scripts/inventory.py` | 공통 파일 순회·메타데이터 목록·변경 보고·자동 목록 생성 |
| `check_index.py` | 한 번 만든 파일 목록에서 이동 후보 조회. 링크 검사와 비싼 전체 원본 탐색 분리 |
| `manifest.py`, `doc_manifest.py` | 필요한 경로 목록을 받아 변경·재검토 대상만 추출. 공통 비공개·순회 규칙 재사용. 텍스트의 출력 전 민감정보 검사와 변환 도구 종료코드 처리 보강 |
| 템플릿·README·설치·기존 CI | 새 생성물·절차 안내와 필요한 파일 배포·검증을 함께 반영 |

새 스크립트의 CLI는 초기에는 기본 조회와 명시적 쓰기만 제공한다. 예를 들어 `inventory.py <vault>`는 변경 보고를 만들고, `--write`가 있을 때만 기계용 목록과 생성 목록을 반영하는 형태다. **제안 문법이며 현재 실행할 수 있는 명령이 아니다.** 의미 색인·원본을 이 옵션으로 자동 수정하지 않는다.

목록화·이동 검색·발췌에서 같은 디렉터리 제외와 비공개 정책을 사용한다. 새 추상화 계층을 크게 만들기보다 실제로 공유할 순회·차단 함수부터 기존 스크립트에 맞춰 분리한다.

## 구조·개인정보·병렬 작업 규칙

- 비공개 장부 누락·오류 시 원본 순회를 중단하는 현재 동작을 유지한다. 비공개 차단은 목록·해시·발췌·이동 검색·캐시 재사용 모두에 적용한다.
- 심볼릭 링크·정션의 순환과 중복 순회를 막는다. 등록된 자료원 밖으로 이어지는 새 링크를 자동으로 따라 자료 범위를 넓히지 않는다. 논리 경로와 실제 대상의 별칭으로 비공개 차단을 우회하지 않게 한다.
- 텍스트와 문서 추출 모두 민감정보 후보를 일반 발췌 출력 전에 검토한다. 현재 `manifest.py`의 본문 검사 공백을 먼저 보완한다. 정규식만으로 모든 비밀정보를 찾아낸다고 보장하지 않는다.
- 파일명 자체에 개인정보가 들어 있을 수도 있다. 기존 비밀정보 이름 필터가 개인정보까지 포괄한다고 가정하지 않고, 해당 후보의 이름·경로를 일반 목록에 그대로 출력하지 않는 정책과 테스트를 포함한다.
- 추출 상태는 도구 없음·시간 초과·비정상 종료·정상 추출이나 텍스트 없음·텍스트 추출 성공을 구분한다. 변환 종료코드와 필요한 오류 종류를 확인하고 원문 내용·비밀값이 섞인 오류 출력을 일반 보고에 복사하지 않는다. 추출 성공도 본문 검토 완료와 별개다.
- 원문 발췌는 현재처럼 볼트 밖 임시 작업 폴더에 두고 작업 후 정리한다. 지속 상태에는 본문 대신 범위·상태·지문을 우선 남긴다.
- 병렬 작업자는 담당 의미 색인만 수정한다. 감독 한 곳에서 목록 기준선·라우터·MOC·비공개 설정·조사 상태를 통합한다. 같은 파일을 여러 세션이 쓰지 않는다.
- 작업자가 읽은 원본이 통합 전에 바뀌면 해당 결과를 최신으로 확정하지 않고 재검토 대상으로 남긴다.
- 생성 목록은 생성기 소유 표식과 기존 내용 일치 여부를 확인한다. 같은 이름의 수작업 문서를 덮어쓰지 않는다. 오래된 생성 페이지 정리는 참조 영향과 소유권을 확인한 뒤 처리한다.

현재 100줄 기준은 유지하되 **읽기 분량도 함께 점검**해야 한다. 문항·본문을 한 줄에 길게 붙여 줄 수만 맞추지 않는다. 문자 수와 예상 읽기 분량을 보고하고, 실제 탐색이 어려운 문서는 질문·프로젝트 단위로 나눈다. 자동 분할로 해설·근거를 자르거나 기존 링크를 잃지 않게 한다.

## 단계별 구현 순서

### 1단계: 목록과 변경 감지

- 등록 자료원과 비공개 정책을 사용하는 공통 순회·기계용 목록을 만든다.
- 안전한 파일 목록과 변경 보고를 생성한다. 오프라인·부분 조사에서 대량 삭제 후보가 생기지 않는지 먼저 검증한다.
- 생성 목록은 기존 수작업 안내를 수정하지 않고 별도 진입점으로 연결한다.
- 같은 실행을 반복했을 때 불필요한 출력 변경·중복 페이지가 생기지 않게 한다.

### 2단계: 변경분 추출과 영향 안내

- 기존 발췌기를 변경·재검토 대상 경로로 제한해 호출한다.
- 텍스트 민감정보 후보의 출력 차단과 문서 변환 실패 상태를 먼저 검증한 뒤 실자료 변경분 추출에 사용한다.
- 링크 역참조로 영향을 받은 안내와 읽을 원문 후보를 제시한다.
- 에이전트의 본문 조사·질문 검증이 끝난 항목만 조사 상태에 반영한다. 단순 파일 목록 갱신은 의미 조사 완료로 세지 않는다.
- 이전 실행의 목록 저장 이후 중단된 의미 검토도 현재 원본과 검토 완료 상태를 다시 비교해 재개한다.

### 3단계: 전반 심화와 평가

- 업무·공용 지식·사이드 프로젝트 등 서로 다른 자료 구조로 같은 흐름을 시험한다.
- 자주 사용하는 질문, 이전에 원문에 도달하지 못한 질문, 파일명과 본문이 충돌한 질문을 검증 사례로 남긴다.
- 성능과 조사 비용을 측정한 뒤 추가 캐시나 내용 검증 범위를 결정한다.

초기 범위에는 벡터 DB, 별도 검색 서비스, 상시 감시 데몬, 자동 스케줄 설치, 원본 폴더 재배치를 넣지 않는다. 필요가 확인될 때 별도로 결정한다.

## 기존 볼트 적용

1. 현재 라우터·영역 색인·MOC·프로젝트 안내와 비공개 정책을 먼저 읽는다.
2. 최초 파일 목록을 만든다. 이를 과거 자료를 모두 조사한 이력으로 소급하지 않는다.
3. 기존 의미 색인은 보존하고 연결 원문과 조사 범위를 대조한다. 근거가 없는 완료 표시는 미확인으로 둔다.
4. 파일 목록 진입점만 추가하고 새 생성물의 쓰기 범위를 검증한다.
5. 변경분 갱신과 질문 중심 심층 조사를 실제 질문으로 시험한다.
6. 이후 조사에서 확인한 항목부터 상태를 축적한다. 추출 실패·기존 깨진 링크·미확인 형식은 사유와 함께 남긴다.

기존 `.secondbrain/topics.json`을 새 전역 분류 체계로 자동 전환하지 않는다. 개인 설정·새 자료원 등록·비공개 장부 전환에 관한 기존 확인 규칙도 유지한다.

기존 스크립트의 자체 테스트와 설치·이식성 검증은 유지한다. 새 순회·실패 처리에는 작은 임시 볼트 기반 테스트를 추가하고, 실제 볼트 검증은 비공개 자료를 제외한 범위를 명시한다. 측정 전 속도·토큰 절감률을 약속하지 않는다.

## 남은 결정

- 사람용 목록의 기본 상세 범위: 모든 안전한 파일을 페이지로 노출할지, 전체 메타데이터 목록과 문서 중심 보기를 함께 둘지 실제 자료원 규모로 정한다.
- 생성 목록의 읽기 분량과 페이지 분할 기준은 작은 자료원·큰 자료원에서 먼저 검증한다. 줄 수만으로 완료 판정하지 않는다.
- 변경되지 않은 메타데이터의 내용 변경까지 검증할 필요와 주기는 실제 운영 요구에 따라 결정한다.

우선 구현할 것은 **원본을 건드리지 않는 깊은 파일 목록과 변경 보고**다. 이후 변경된 근거를 따라 의미 색인과 질문 검증을 갱신하는 흐름으로 확장한다.

## 구현 결과 (2026-11-09)

- 1~2단계를 구현했다. 공통 순회·차단은 `scripts/sources.py`, 목록·변경 보고·재검토 대상·역참조·생성 목록·검토 기록은 `scripts/inventory.py`(기본 읽기 전용, `--write`, `--mark`, `--review-out`, `--all`, `--accept-source`). 절차는 `references/incremental-sync.md`, `references/catalog.md`, 기존 1~5단계는 `references/index-update.md`로 옮겼다.
- `check_index.py`: 이동 후보를 저장된 목록 또는 1회 순회 조회표로 찾고, 읽기 분량(자 수·최장 줄)을 줄 수와 함께 보고한다. 링크로 연결된 최상위 `.md`는 읽거나 정규화하지 않는다.
- `manifest.py`·`doc_manifest.py`: `--paths`로 대상 제한, 텍스트 민감정보 출력 전 차단, 변환 상태 코드 구분(오류 문구 미출력), 형식별 실제 추출 범위 표시, 볼트·원본 안 출력 거부.
- 검증은 임시 합성 볼트의 자체 테스트로만 했다(macOS). 실제 볼트에는 실행하지 않았다.

남은 한계: 메타데이터가 같은 내용 변경은 잡지 못한다. 이름의 개인정보 검사는 정규식이라 사람 이름을 못 찾는다. 오프라인 비공개 경로의 별칭 차단은 마지막 `--write`에서 저장한 해시에 의존한다. 비공개 비교는 대소문자를 무시하므로(대소문자 무시 파일 시스템 대응) 대소문자 구분 시스템에서는 이름만 대소문자가 다른 경로까지 보수적으로 막는다. `catalog.md` 자체는 쪽으로 나누지 않는다. 3단계(서로 다른 실제 자료 구조의 질문 시험, 성능 측정 후 캐시 결정)는 남았다.
